# T007: G0 feasibility lock

## Outcome and boundary

G0 passes as a feasibility and architecture decision checkpoint on the measured Linux ARM64 environment. It does not pass any editor release-performance, Vim-parity, terminal-matrix, or cross-platform gate. The prototypes remain disposable and are not production dependencies. No Xi application runtime exists in this repository yet.

The decision is based on T001–T006 and T084 evidence reports. Their runnable commands and artifacts are listed in [T007 evidence](../evidence/T007.md). All unresolved product work remains owned by the existing tickets cited below; this audit found no orphaned G0 discovery requiring a new ticket.

## Locked choices

| Boundary | Feasibility decision | Evidence and production owner |
|---|---|---|
| Supported baseline | First implementation and qualification target is Linux ARM64. This is the only platform/native package actually probed; no macOS, Windows, or other architecture support claim is made. | T001/T002; T062 owns reference-host and final platform qualification. |
| Runtime and dependencies | Use Bun `1.3.13` as the measured baseline; TypeScript `7.0.2` with the repository's strict options; `@opentui/core` `0.5.11` and its verified Linux ARM64 native artifact. Keep exact package versions and integrity in `package.json`/`bun.lock`. The package's Bun engine range is broader (`>=1.3.13 <2`), so controlled qualification must set `XI_REQUIRED_BUN_VERSION=1.3.13`; there is no CI release runner yet. Neovim `0.12.4` is a pinned development oracle only and is prohibited at runtime. Node compatibility runtime and Python are tooling observations, not Xi runtime pins. | T001/T003 evidence. T004 and T005 record different Node compatibility versions (`v24.3.0` and `v24.19.0`); Node is not a product dependency, so no Node pin is inferred. |
| Text and storage | Public document positions use UTF-16 code-unit offsets, explicit document versions, and reject offsets inside surrogate pairs. Select a persistent chunked rope with surrogate-safe leaves capped at 1,024 UTF-16 units and subtree UTF-16/LF aggregates. Keep leaf representation private behind the document contract. | T004 measured the same 100,000-insert output with 539 rope chunks, 616,212 retained heap bytes, and 66,752,512 RSS bytes, versus 100,002 piece descriptors, 40,212,685 heap bytes, and 95,412,224 RSS bytes. T009 owns production storage and the prototype-specific budgets. |
| Rendering | Keep OpenTUI at the disposable UI boundary: a custom `Renderable` consumes visible rows and dirty spans; it does not own editable text. Internal viewport cells are zero-based; conversion to OpenTUI terminal cursor coordinates happens at that boundary. Retain OpenTUI's native buffer diff. | T002 public-API prototype and visually reviewed xterm captures at 120x40 and 240x70. Product layout/render packages and T062 own integration and qualification. |
| Terminal input and pointer | OpenTUI's pinned parser/renderer is the single byte decoder. Normalize its callbacks once into canonical key, paste, focus and pointer events; use zero-based terminal cells and keep paste/raw diagnostics byte-exact. Set `exitOnCtrlC:false`; own UTF-8 boundary protection, terminal modes, suspend/resume and cleanup in the UI/platform adapter. Prefer button-motion plus SGR coordinates for mouse; do not enable all-motion reporting without a measured feature need. | T006/T084 PTY/parser evidence. T035 owns production decoding and raw-byte fidelity; T085 bounds frame coordinates before hit testing; T086/T094 own gestures, terminal restoration and named terminal matrix. |
| Vim patterns | Xi owns a Vim-dialect parser and explicit IR. Do not translate to JavaScript `RegExp` or ship Neovim as an engine. Use a bounded NFA for the regular subset and bounded backtracking where Vim constructs require it, with typed unsupported/budget errors and resumable cancellation over immutable snapshots. | T005 feasibility evidence; T026 owns evaluator, T027 owns search/substitution commands. |

These are architecture choices supported by prototypes, not implementation contracts complete enough to import. Production work still needs the owners' public contract tests and acceptance evidence.

## Unresolved incompatibilities and failure cases

- `INP-UTF8-CHUNK-LATE-01`: OpenTUI's 20 ms parser timeout can turn a delayed valid UTF-8 code point into two key events. A disposable guard preserves a 25 ms split; production routing remains T035 work.
- `MP01-X10-RAW-HEX-01`: X10 wire bytes `1b5b4d20ffff` appear in the string carrier as `1b5b4d20c3bfc3bf` after UTF-8 re-encoding. T035 owns exact-byte preservation. X10 also tops out at zero-based coordinate 222 and lacks pressed-button drag tracking (`MP01-X10-LIMIT-01`, `MP01-X10-MOTION-01`).
- `MP02-COORDINATE-OVERFLOW-01`: an oversized SGR decimal coordinate becomes approximately `9.999999999999999e35`; T085 must reject or clip it against a valid frame before hit testing.
- `MP01-SGR-RELEASE-01`: one captured release emits `drag-end`, `up`, `drop`, and a second `up` at OpenTUI's renderer API. T084's adapter coalesces the callbacks; production must regression-test the pinned-version behavior.
- Emulator behavior remains unqualified: T084 used a kernel PTY with `TERM=xterm-256color`, not an xterm emulator. Shift bypass, real terminal mouse forwarding, tmux/SSH paths, Kitty negotiation and all-motion cost remain for T086/T094/T062. No terminal beyond protocol injection is certified.
- `PATT-CATASTROPHIC-01` hits the 50,000-step work budget after 50,001 steps (latest proxy 25.570 ms); the prototype synchronously materializes/scans the input and cannot yield. T026 must replace this path before interactive use.
- T003's pinned oracle has 597 inventory entries, all `unimplemented`; 89 remain provisionally routed to T061. Oracle asset qualification is Linux ARM64 only.
- Native OpenTUI loading passed on Linux ARM64 (`4cedc1bc…57c23`). Other platform/package artifacts have not been tested; no wider native-support claim follows.

Failure IDs above reproduce the discovered input, pointer, pattern and inventory gaps. They are assigned to existing tickets: T035, T061, T062, T085, T086, T089 and T094; no ticket is marked done to hide a gap.
