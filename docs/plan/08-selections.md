# First-class selections and Vim composition

This is a required release contract. Multiple cursors are available in the initial editor, share the owned Vim engine, and are not postponed to a plugin or simulated with macros. The [research](11-interaction-research.md) distinguishes upstream observations from these Xi design decisions. The single-cursor strict profile continues to meet [the complete Vim contract](02-vim.md).

## Three distinct concepts

1. **Semantic selections:** every editing session has a nonempty selection set, including a one-cursor session. Vim Normal cursors, Insert carets and Visual character/line/block regions retain their different meanings.
2. **Multiple cursors:** explicit selection commands add members to that same set. One shared Vim parser/mode dispatches a command over the set. This is an extension of command cardinality, not a switch to Helix's selection-first grammar. `dw`, `ciw`, `f`, counts, registers and Visual mode keep their Vim meanings at each applicable cursor.
3. **Motion trail:** optional paint showing a completed motion's extent. It is never a semantic selection or a default edit target. Its specification is in [interaction](09-interaction.md).

Helix-style selection manipulation is exposed by named Xi commands and leader bindings, without stealing Vim `s`, `x`, `C`, `,`, `;`, `%`, `U` or `q`. The strict profile starts with one cursor, has no added leader bindings and no motion trail. Explicit `:Xi` commands can opt into the extension; such traces are labeled Xi semantics, not Neovim multi-cursor parity. Returning to a singleton uses the same core data structures and engine.

## State, units and ownership

`packages/selections` owns pure immutable selection constructors, canonicalization, set transformations and selection change descriptions. It imports document public read/mapping APIs and primitives, never UI, Vim or services. It owns no text or mutable live session. Document supplies batched anchor/change mapping. Vim owns live editing-session state per `ViewId`; workbench owns session creation/focus/disposal and reads its snapshots. Layout projects snapshots; services only propose changes. Shared registers/history scopes follow the Vim contract, not an accidental per-widget store.

The public `SelectionSet` contains `documentId`, `documentVersion`, `selectionGeneration`, `primaryId`, and a nonempty collection of immutable members. IDs survive movement, sort and mapping; array indexes are not identities. Each member has `SelectionId`, anchor/head positions in validated UTF-16 units, endpoint affinity, semantic kind, direction, desired logical/display column and applicable virtual-cell/block metadata. Use a discriminated union so an Insert caret cannot accidentally acquire Visual block width. All members use one session mode and one Visual kind; multiple blocks may each have different dimensions. Pending counts/register/operator prefixes belong to the shared parser, while motion results, desired columns and replace stacks can differ per member.

Normal cursor positions name Vim semantic characters, with an explicit empty-line/EOF representation. Insert positions name gaps. Visual endpoints preserve Vim inclusivity/options until the Vim range normalizer produces half-open edits. A `SelectionSet` must not erase those distinctions by interpreting every `anchor === head` as an empty edit. Document half-open text ranges, engine selection endpoints, syntax ranges, LSP positions and painted cells are distinct contracts.

Two views of the same document have separate sets and scroll positions. Selection-only changes increment `selectionGeneration`, not `documentVersion`, and do not create dirty text, LSP didChange or document undo entries. Asynchronous selection-sensitive requests carry both generations and the view identity; document version alone cannot detect a moved cursor. Closing a view cancels those requests. History stores serializable before/after selection values for the originating edit, not live objects or required references to a closed view.

## Canonicalization and conflicts

Canonical iteration order is document order by normalized start, end, then stable creation ordinal. Primary identity remains explicit after sorting. In a merged component, retain the primary member if present, otherwise the oldest member; preserve the retained member's direction and identity. Emit an old-to-new ID map so snippets and status models can invalidate or remap deliberately.

Exact duplicate carets collapse, including after a transaction maps two carets to the same position. Nonempty compatible character selections merge only on actual overlap; adjacent selections stay distinct. A caret inside a character range, including its left boundary but excluding its right boundary, merges into that range. Different semantic kinds are not implicitly combined; an explicit conversion command is required. Line/block geometry is normalized by Vim before edit conflict analysis; flattening a block into one continuous character range is forbidden. Block components are only merged if their union can be represented without selecting additional cells; otherwise preserve components until edit planning.

Edit conflicts are a separate step: independent motions can produce overlapping operator ranges even from distinct cursors. Resolve all intents on one immutable base version. Identical edits (same range and replacement) are deduplicated, with all cursor outcomes retained. Overlapping pure deletions can union; register capture still uses the canonical pre-edit selections. Nonidentical replacements, coincident inserts with different text, or insertions inside a replacement are conflicts and reject the whole command before text, registers, history or mode changes. Adjacent nonempty edits are valid. Insertions at a replacement boundary require an explicit composition rule in that command's fixtures; the generic planner rejects ambiguous cases. The generic document transaction API rejects coincident insertions and insertions directly touching a nonempty edit; a command with a reviewed composition rule must combine them into an unambiguous edit before commit. Document never guesses how to resolve an invalid batch.

Example: two `dw` ranges overlap; the union is deleted once and there is one history entry. Two `c` operations request different replacement text for an overlapping region; neither is committed. Adding the same caret twice then typing `X` inserts one `X`. A failed mutating motion at any member rejects the multi-command; a nonmutating motion can leave the failed members in place, move the others and report the failed count. Neither rule changes singleton oracle behavior.

## Command planning and commit

Every command descriptor declares a selection policy; omission is a registration error. The compatibility inventory adds that policy and Xi fixture IDs for every owned command. New commands cannot silently default to the primary cursor.

| Policy | Semantics | Required examples |
|---|---|---|
| `per-selection` | Resolve against each member of the same base; canonicalize one combined outcome | Motions, text objects, operators, insert/replace, numeric changes, put, Visual operations |
| `selection-set` | Operate on membership/primary identity once | Add/skip/keep/rotate/split/merge selections |
| `document-once` | Run once on the shared document/history; map all selections | Undo/redo, explicitly addressed Ex edits, whole-document formatting |
| `primary-navigation` | One host navigation based on primary; retain source set for return | Definition, tags, `gf`, jump navigation, hover |
| `primary-state` | One inherently scalar Vim state update from primary, visibly documented | Setting a named mark, inspecting cursor position |
| `workspace-once` | One operation independent of cursor count | Save, quit, file picker, workspace rename/edit, Git |

Command-specific provider or grammar limitations have an explicit disabled reason before dispatch. All local built-in motion/operator/edit families remain required; “multi-cursor unsupported” is not an acceptable blanket policy. Context-dependent commands receive a reviewed per-family policy and tests. Ex addresses remain Vim addresses: `:s` defaults to the primary current line once, `%s` runs once over the buffer, and `:global` selects lines once. Disjoint selections do not imply a new meaning for `'<,'>`. Multi-Visual Ex uses the primary selection's mark range, displays that scope before execution, and offers a separate explicit Xi command for applying an operation to disjoint ranges. External filters gather range jobs under the coordinator, preflight all results and commit one combined edit; they never spawn unbounded processes per cursor.

Shared Vim state needs explicit reduction: the search pattern/direction and last-find character/direction are recorded once per logical command; each member resolves against its own position. Interactive native search previews all members, cancellation restores the full prior set and viewport, and its shared state commit follows the documented multi-command failure policy. `n/N` and `;/,` reuse that shared state per member. Native marks name one location and are set from primary; jumping to a mark uses primary navigation instead of collapsing every member onto it. Native jump/change lists record primary locations once per logical command, with separate richer workbench return state. `gv` retains prior Visual shapes by stable member identity; new members without a prior shape block multi-reselect with an explicit reason. These policies, options and relevant special marks require inventory fixtures, not implicit last-cursor-wins updates.

Pipeline: snapshot session/document/config → parse once → resolve per policy → validate ranges and all state deltas → prepare text and selection result → commit document and install matching engine state → publish ordered read-model changes → run post-commit effects. The coordinator prevents reentrant commands until the text and engine state agree. A register write, macro step, mode transition or dot target must not become observable for a rejected edit. Preparation may yield on large operations, but is cancellable and verifies both document and selection generation before commit. No partial multi-cursor text is exposed during yielding.

Insert text and bracketed paste broadcast as text, with per-cursor indentation under the active profile. Replace mode retains a replace stack per member and preflights destructive backspace across the set. A shared insert session and its triggering `c` form the documented Vim undo group. A paste containing escape bytes is never parsed as a sequence of commands. Directory and commit buffers use these same editing paths; directory identity validation still happens at filesystem-plan apply, not at every keystroke.

## Registers, repeat, history and macros

Singleton register semantics remain exactly oracle-driven. A multi-yank/delete produces an ordered vector of typed register fragments plus the primary fragment's index. The register owner keeps this vector as Xi metadata alongside the native scalar value, which is the primary fragment. Numbered-register rotation and append happen once per command, not once per cursor. A singleton native write to a register replaces its scalar and clears its vector. Black-hole writes update neither representation. Named append concatenates corresponding vector fragments only with equal arity and compatible types; otherwise the whole append fails with an actionable reason. Mixed line/character/block values require an explicit conversion, not dropped metadata.

Multi-put broadcasts a scalar to every member. A vector of matching arity distributes fragments in current canonical selection order; cardinality mismatch fails without editing and offers explicit “broadcast primary fragment” or “join fragments” commands. A singleton put reads the native scalar even if vector metadata exists. System clipboard export is an explicit newline-joined plain-text representation; internal vectors are retained only in Xi registers, never inferred from arbitrary clipboard newlines. Clipboard reads paste plain text at every cursor by default. Clipboard failure reports the failed effect without claiming that a successful document deletion was undone.

`.` stores the semantic multi-command and insertion recipe, not old coordinates or old cursor count. It resolves at the current selection set. Selection creation itself is not a dot target. Per-cursor inserted text can broadcast when identical; differing insertion recipes require matching arity or an explicit conversion. Repeat count replacement follows native rules per member. The retained multi-repeat target remains a labeled Xi target after collapsing to one cursor until replaced; scalar-compatible recipes work there, arity-dependent recipes reject clearly. It is not silently reinterpreted as a strict Vim target.

Undo/redo/earlier/later act once on the document undo tree. On an edit's originating live view, restore its before/after set; if invoked from another view, map that invoking set through the revision and preserve other views' independently chosen selections except for their required position transforms. Never resurrect a closed view. Selection manipulation has its own bounded session history (default 100 states); `selection.undo` restores membership/primary without editing text and stops at an unmappable history boundary with a reason. Document `u` is never repurposed for selection undo.

Record one logical input stream for macros. Playback dispatches each command once through its policy over the current set; do not run the entire macro independently to completion at each cursor. Macro selection commands use current context and can change cardinality deterministically. Stop on a failed multi-edit, retaining previously committed macro commands; cancellation is between atomic commands. Register-vector data is not executable macro text; macro playback requires a scalar macro register. Test nested macros, selection changes, mode changes, counts and cancellation independently from dot.

## Creation and manipulation UX

Required command IDs: `selection.add-above`, `selection.add-below`, `selection.add-next-match`, `selection.skip-next-match`, `selection.select-all-matches`, `selection.split-lines`, `selection.select-regex`, `selection.keep-matching`, `selection.remove-primary`, `selection.keep-primary`, `selection.rotate-primary-next`, `selection.rotate-primary-previous`, `selection.collapse`, `selection.flip`, `selection.merge`, `selection.undo`. `selection.expand-syntax`/`shrink-syntax` use validated language/syntax providers when present. Empty filtering preserves the prior set and explains “no selections remain”; removing the last member is a no-op. Newly added members become primary; removal chooses the next member in document order with wrap.

`collapse` retains all heads and enters Normal; `keep-primary` retains the current mode/kind and primary member. `flip` swaps Visual endpoints without changing membership. Split-lines creates one character Visual selection per nonempty intersection of the selected regions with a logical line; an entirely empty selected line receives its explicit empty-line representation. Regex/syntax selection creation enters character Visual and uses explicit engine endpoint conversion; line/block to character conversion is visible as a mode-kind change. Generic selection merge cannot erase a block's ragged geometry. A second Esc after leaving Visual keeps primary only under the Xi idle-Normal binding.

Add-above/below uses logical lines and each source member's desired display column, clamps at short lines according to the current Vim virtualedit policy and skips existing duplicate carets. Repeated commands extend the outermost selection frontier in that direction; wrap-aware variants have separate IDs. Normal `add-next-match` starts with the Vim word under primary (`iskeyword`); an existing character Visual selection uses its exact text. First invocation materializes that text as a Visual selection; subsequent invocations add the next nonoverlapping occurrence and retain Visual mode. Literal case-sensitive matching is default, with visible configurable flags. Skip-next advances the occurrence scan without adding. Select-all searches the entire current buffer; select-regex searches only the currently selected regions using the owned Vim dialect. Neither changes native `/`, `n`, `*` state unless explicitly invoked as a native command.

Selection searches run over a versioned snapshot, integrate membership once, show count/progress and cancel without leaving a partial set. Zero-width regex results advance by a valid semantic boundary, including a single EOF match. The release ceiling defaults to 10,000 members: exceeding it leaves the old set intact with a count/limit message and narrower-scope commands; no silent truncation. Keyboard-only flows cover create, edit, inspect primary, skip, undo, collapse and return. Status displays `NORMAL · 4 cursors` or the active Visual kind with count; the primary is always identifiable. Esc first cancels pending input/exits Insert or Visual under Vim rules; a subsequent Esc from idle Xi Normal keeps primary. Strict idle Esc does not acquire that binding.

## Language services and session continuity

Service responses include originating view, document version, selection generation and request generation. A move, membership change or primary rotation invalidates a positional completion even when no text changed. Hover/signature/navigation request at the primary; primary navigation stores the full source set in the workbench return context. Native jump-list semantics remain in Vim and are not replaced with that richer workbench context.

Ordinary multi-cursor completion and snippets are required. Query at primary; broadcast a simple completion only when each cursor has equivalent validated prefix/replacement context. Compute each local replacement range from that cursor's own snapshot context, never by translating the primary server offset blindly. Accept one batch. Apply identical document-wide additional edits (such as an import) once after checking that they do not overlap any local replacement. Server commands execute once. Incompatible contexts or opaque server edits disable multi-accept and explain why; an explicit primary-only acceptance may edit primary and map the other cursors, but must not discard them or pretend to have completed all. Per-cursor server requests are a bounded explicit strategy, not a mandatory background fan-out.

Snippets instantiate one placeholder graph per compatible member, with synchronized Tab progression and member-local mirrors/transforms. A topology mismatch blocks acceptance before editing; cursor merge, external edits through placeholders or selection membership changes cancel the snippet session coherently while retaining committed text and mapped cursors. Formatting and workspace edits apply once through document transactions and transform all sets. Selection-range requests can carry all supported positions; validate returned nesting and per-position correspondence. Multi-root URIs never leak into a single-document selection set.

Session persistence stores versioned semantic sets separately from text recovery, validates restored offsets against matching content identity, and maps using recovery deltas only when the base is known. Otherwise restore the primary at a safe location with an explanation that stale secondary selections were not restored. Focus changes preserve selections, cancel incompatible pending parser state, and close an Insert undo group according to the documented focus transition. Selection-count or mode changes never result from an unrelated background refresh.

## Required evidence

`MC01` singleton-equivalence across the full strict inventory; `MC02` stable IDs/primary and set transformations; `MC03` batch conflicts and atomic state; `MC04` counts/operators/Visual kinds/Unicode; `MC05` Insert/Replace/paste; `MC06` register-vector and clipboard rules; `MC07` dot/undo/branching; `MC08` macro dispatch/cancel; `MC09` creation/filter/regex/selection undo; `MC10` independent views and session restore; `MC11` completion/snippets/additional edits/staleness; `MC12` scale and cancellation. These are fixture families to implement, not evidence already obtained.

For independent nonoverlapping cursor cases, run the same command on isolated identical Neovim snapshots per cursor, compare local outcomes, then compare Xi's composed result with a separate test model. Overlap policy, vector registers and cardinality changes use the explicit Xi specification and hand-reviewed golden fixtures/property laws, not fabricated Neovim expectations. Required laws include singleton equivalence, permutation invariance with stable primary, duplicate-insert idempotence, transaction round-trip, no partial failure, and mapping composition. Register/direction-sensitive cases must not be normalized away to satisfy those laws.

Benchmark 1/10/100/1,000/10,000 cursors, sorted/reversed creation, coincident/overlapping ranges, long lines, Unicode, split views, and undo retention. Sort endpoints once and batch-map through the change set; forbid an O(selections × edits) transform. Aim for O((S+E) log(S+E) + changed text/storage work), with O(S+E) mapping for sorted endpoints. Full command cost must include resolution, storage, history and rendering, not just the mapping kernel. The scale thresholds and gates are in [validation](05-validation.md).

## Resource contract

Selection arrays, vector registers, originating/other-view history and old snapshots are byte-accounted together; sorted mapping retains its O(S+E) contract. No pool or scratch reset may change a published selection set. Large delete/undo and long Insert groups must preserve required semantics within the explicit large-operation profile. See [performance engineering](12-performance.md).
