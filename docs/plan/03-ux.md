# Keyboard and visual specification

The interface should feel quiet, stable and intentional. The editor owns most of the screen; panels appear when useful and remember their state. No welcome dashboard must interrupt opening a filename. Every available action has a searchable command, every focus change is visible, and a slow service cannot trap editing.

[09-interaction](09-interaction.md) is the normative companion for prefix/Ex suggestions, aliases, multi-cursor keys, mouse gestures and motion-trail styling. [08-selections](08-selections.md) defines semantic state and [10-extensibility](10-extensibility.md) defines shared metadata. Mouse workflows are required in addition to keyboard-only paths.

The references provide Explorer/Outline hierarchy, grouped search results, and source-control/diff composition. Xi adapts their jobs to cells rather than reproducing large desktop chrome. OpenCode supports configurable themes and light/dark variants; Xi's proposed palette below is original and is not claimed to reproduce OpenCode's exact colors. [OpenCode themes](https://opencode.ai/docs/themes/).

## Layout

At 120x40: optional one-row buffer header; sidebar about 28 cells (clamp 22–40 and at most 35%); editor at least 60 cells where possible; bottom panel initially hidden and, when opened, about 10 rows; one status row. Separators are single-cell rules, with no repeated nested boxes. Sidebar header has text labels for Files, Search, Git; inactive modes do not each reserve vertical space. Outline appears under Files only when the active language provides symbols; a pending/failed capability has an explicit state.

Transient status notices expire: informational messages remain for 5 seconds and errors for
8 seconds. A newer message replaces and cancels the older expiry so stale timers cannot clear
current feedback.

This is an information-layout sketch, not a validated cell-perfect snapshot. T034 creates actual OpenTUI fixtures at 80x24, 120x40, 160x50 and 240x70. Below 100 columns, hide the sidebar by default and open it as an overlay. Below 80 columns, use one editor and unified diffs; preserve hidden split state. At 60x18, prioritize editor, mode/path and a compact picker. Below 40x10, show a compact “terminal too small” state while retaining buffers and accepting resize/quit safely. Resize must not discard edits, queries, selections or focus history.

Editor groups use a split tree with minimum sizes. Geometry drives screen-line Vim motions; it is not recomputed inside the motion engine. A buffer may appear in two views, each with cursor/scroll state and shared text/history. Preview opening changes one unmodified preview slot; first edit or explicit pin promotes it. Closing a dirty buffer offers Save, Keep open, and Discard with clear consequences. Switching focus alone must never discard or save.

Empty/loading/error/partial/stale states must be styled with the same care as populated states.

## Input and focus

Focus contexts: editor-normal, editor-insert, editor-visual, editor-commandline, panel-navigation, query-input, directory-edit, commit-edit, picker, menu, modal-review, and future terminal-input. Route one event to one active context. A modal overlay captures input and remembers the previous target/cursor; closing restores it unless that target no longer exists, in which case choose the active editor. Background responses cannot move focus.

Esc closes the top overlay or cancels the current pending command according to context; in insert it returns to normal. A second Esc may clear transient highlights only through an explicit mapping. Esc cannot accidentally dismiss a dirty directory draft. Ctrl-C must not be bound to unconditional application shutdown. Bracketed paste is a text event and may contain newlines or escape-looking bytes without executing commands. Legacy terminal ambiguity (Tab/Ctrl-I, Enter/Ctrl-M, Esc/Ctrl-[) is reported in keymap inspection rather than “fixed” by dropping a native binding. Enhanced keyboard support is negotiated; key release/repeat events are handled deliberately. [Kitty keyboard protocol](https://sw.kovidgoyal.net/kitty/keyboard-protocol/).

Terminal read boundaries must not change valid typed text: buffer incomplete valid UTF-8 code points across chunks, independent of Escape's ambiguity timeout. If input proves invalid or ends mid-code-point, surface U+FFFD as text rather than reinterpreting high bytes as Alt commands. The pinned OpenTUI 0.5.11 renderer currently applies its fixed 20 ms parser timeout to incomplete UTF-8 as well; T006 measures that limit, and the production adapter must preserve this contract.

In panels, `j/k`, arrows, `gg/G`, Ctrl-D/U navigate rows; `h` collapses or returns to parent, `l` expands; Enter activates; `/` filters; Esc clears filter before returning focus. In a text field, typing `j` inserts j; Tab/Shift-Tab traverse controls and Ctrl-N/P traverse results when shown. Panels expose a command to enter their normal/navigation mode; users are never forced to guess whether the same key will type or move.

## Default keys and profile distinction

The strict engine profile leaves native keys, including Space, alone. The default Xi workbench profile opts into Space as leader and displays that fact in its profile description; it inherits native editing otherwise. The optional personal profile imports the known deviations separately. Prefix hints appear after 250 ms without delaying a complete command; Xi user-mapping resolution timeout defaults to 500 ms and is configurable. Native incomplete grammar prefixes have no new hint timeout; strict timing follows pinned options. Timing settings are part of the parity fixture profile.

The theme picker opens with the currently applied theme selected and scrolled into view.
Hovering a result selects and previews that exact theme immediately. Arrows and Ctrl-N/P
move one result; Ctrl-U/D move half the visible result area; PageUp/Down move a full page.
Click or Enter commits the selected theme; Escape restores the theme from before opening.

## Journeys and acceptance behaviors

### Files and Outline

Open workspace → focus Files → expand `src` → type `/editor` → Enter opens file and focuses editor → reopen Files restores selection and scroll → Outline follows the active document. File tree selection is stable by path/identity, not row index; watcher insertions above it do not change the chosen file. Auto-reveal expands ancestors without stealing focus or continually scrolling a manually browsed tree. Outline uses hierarchical document symbols, shows detail/kind on demand, and tolerates empty results or servers returning a flat list.

When LSP is unavailable, Outline is absent or shows a concise unavailable state if explicitly opened. Do not synthesize a fake LSP outline from regex. A syntax-based fallback can be labeled separately if later implemented. Collapsed nodes, file sorting, ignored/hidden switches and panel width persist per workspace.

### Directory as editable text

`Space O` opens an editable directory document with current directory and breadcrumb/optional Miller columns. Each entry has a stable opaque identity, immutable metadata decoration and editable escaped name. Native Vim rename/delete/yank/paste/macro operations edit this draft. `:w` compiles a filesystem plan and opens a compact review listing creates, moves, copies and trash operations; Enter on Apply executes only that reviewed plan. The review has its own focus state; plain Enter while editing a filename inserts/moves according to Vim.

Unknown or ambiguous identity after arbitrary text editing must produce a validation error, not guess a rename. A copied row with duplicate identity becomes an explicit copy candidate only under a documented rule; otherwise request resolution. Names containing newline/tab/control bytes use reversible escaping and a raw-name detail view. `u` before apply undoes draft text only; an applied operation has a separate restore action backed by the journal. Conflict errors point to the row and retain the draft. T042 tests rename cycles, case-only names, cross-device moves and changes made outside Xi.

### Workspace search and replace

Focus query and type → results stream in file groups with an updating count → Ctrl-N/P previews matches without transferring focus → Tab enters results navigation → Enter opens a match → Esc returns to the original query/results context. Query flags and include/exclude controls have visible shortcuts via help; the query is never hidden behind an icon. Regex errors are inline, preserve the last valid result set as stale, and do not execute an unintended query.

Expand Replace → enter replacement → choose match/file/all scope → see exact proposed edits and changed file count → apply selected plan. Search results include unsaved open buffers and clearly identify them. Changes between preview and apply cause revalidation, not blind offset writes. Match exclusion is persistent for that query generation. Large result sets remain navigable while streaming and show truncation explicitly. Details are in [services](04-services.md).

### Language actions

A diagnostic badge is discoverable through `Space d/e`; choosing one shows message, source, code and actions. `Space a` gives only supported/current actions, displays disabled reasons, and previews multi-file/destructive edits. Hover is keyboard-scrollable and can be pinned; ordinary hover never traps insert typing. Rename collects a new name, displays validation errors in place, and previews multi-file edits. Cancelling restores source focus. An unavailable server offers installation/configuration information without auto-downloading software.

### Git

Focus Git → navigate Staged, Changes, Untracked and Conflicts → Enter opens a diff → `]c/[c` navigate hunks in diff context → an explicit Stage hunk command applies the selected verified patch. Staging and unstaging are separate command IDs; `s/u` are available only in Git navigation, never intercepted while editing text. Width determines unified versus side-by-side display. The UI labels BASE/INDEX/WORKTREE/BUFFER identities precisely; unsaved content is not shown as a stageable disk diff without an explicit save.

Comparison editors have a distinct tab/view identity from ordinary file editors. A working-tree comparison shares the file document, undo history and save identity; its original side is an immutable syntax-highlighted snapshot. Opening focuses the first actual change, not line one or the hunk's leading context. Wide editor areas align both sides with noneditable filler rows; narrow areas interleave removed original rows and editable current rows with numbered `+/-` gutters. The entire current file remains navigable and editable. Removed rows never acquire editable document coordinates. Closing a comparison does not discard the file's unsaved edits. Index comparisons remain read-only. These requirements supersede the earlier file-decoration-only interpretation; T057 remains open until its full acceptance and performance evidence are satisfied.

Commit opens a Vim text buffer with a persistent draft and staged summary. Submit is an explicit command, disabled for an empty message/no staged changes unless a named Git option permits it. Hooks/signing errors preserve message and staged state. Push/pull/fetch are explicit separate commands. Discard shows the exact path/hunk scope and recovery choice. Conflict resolution tracks base/ours/theirs/result; inserting conflict-marker-looking text does not automatically prove resolution.

## UX review gate

Additional required journeys: create selections by keyboard and mouse, `ciw`/insert/repeat/undo once, return to primary; discover pending commands and execute `:q` safely with aliases/help; drag through wrapped Unicode text and resize a split; compare motion-trail on/off without changing edits. These are E19–E25 in [validation](05-validation.md). Native `:q` errors and explicit workbench Save/Keep/Discard close reviews are separate behaviors.

For every journey, cover keyboard-only success, cancel, back, loading, empty, failure, stale response, narrow viewport and reopen. Capture actual rendered cells and terminal screenshots in light/256-color/ASCII modes. Review alignment, hierarchy, selected-row contrast, cursor visibility, clutter, truncation and focus return. Automated snapshots establish regression detection; a named visual review of real rendered output establishes whether it looks polished. No component passes solely because it renders without throwing.

## Resource-aware presentation

[Performance](12-performance.md) governs the paint/cell path even though ordinary UI chrome remains idiomatic TypeScript. Virtualized panels, previews, output rings and native OpenTUI buffers have byte/lifetime budgets. Degraded syntax/full-sync services and result pagination are visible; no silent truncation of replace/all-selection actions. Under pressure preserve input, unsaved edits, coherent history and capture/release events. No additional performance dashboard is required.

### Editor refinement acceptance (2026-09-20)

A theme scope alone does not enable a full-height cursor column. Keep the cursor-line treatment without the distracting vertical stripe. Horizontal split buffer strips occupy the boundary row themselves; tab/close controls stay clickable and unused strip space remains a resize handle. Vertical splits retain a one-cell divider. A successful empty/whitespace hover result closes silently; a pending or empty result never displays a “No hover information” popup. Theme picker overlays cover a full-height sidebar, including all text rows, on dark and light previews. Last-motion ghost selection and explicit `v` adoption follow spec 09.
