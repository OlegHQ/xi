## Observable result

`apps/xi/src/main.ts` composes the document, owned Vim session, persistence service and OpenTUI terminal through public entrypoints. The first-frame service entrypoint avoids the complete services barrel. The editor painter reuses stable visible rows and repaints only damaged rows for ordinary cursor movement; resize, scrolling, visual selection and decorated transitions retain full repaint behavior. Optional UI surfaces and language initialization are deferred from the first editable frame, with file indexing started when the file picker is first requested.

The launcher now starts native OpenTUI renderer creation as soon as the UI adapter is loaded, overlapping it with the remaining workbench composition. Small files use one bounded read; large files retain the streaming persistence path.

## Failure cases and recovery

The production PTY fixtures cover startup/quit, split close, insertion, save, Ex write/quit, file picker cancellation, Explorer refresh and live completion. The diagnostic key producer preserves all 30 sequential events and observes output for each. Open-loop held/burst input, slow-reader backpressure, full service-load activity, cold cache, arrows/mode transitions, Unicode edits, long history, correctness replay and physical capture remain unmeasured.

One aggregate run exposed an Explorer PTY fixture race when two external
filesystem mutations were issued at the refresh callback boundary. A 100 ms
fixture settling interval now yields 8/8 standalone passes and a passing
24-fixture aggregate rerun; no production watcher code changed.
