## Observable result

`SemanticTokenStore` decodes full, delta and range token responses into immutable UTF-16 spans, validates legends and data bounds, requires a matching result baseline for deltas, and rejects older document versions/generations. The editor projection clips semantic decorations to one visible row and a hard span cap without parsing or mutating text.

## Performance and visual evidence

Token decoding is linear in the bounded protocol array and row projection stops at the configured cap. Semantic decorations are paint metadata; syntax remains the fallback layer. Terminal screenshots are owned by T087/T063.

## Failure cases and recovery

Invalid data length, negative fields, unknown token types, changed legends and out-of-range delta edits return typed failures without publishing a partial snapshot. A stale response cannot replace newer text. Clearing/disposal releases snapshots.

## Limitations and next action

Server capability negotiation and request scheduling remain in the LSP session owner; this store is the versioned response/cache layer. T067 owns semantic-dependent folding/hints integration.
