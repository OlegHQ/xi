## Observable result

`packages/vim/insert/multi.ts` composes the existing singleton Insert/Replace planner over a non-empty, stable-ID member set. Every member resolves against one document snapshot; edits are normalized through the atomic multi-command conflict policy, duplicate inserts are deduplicated, per-member literal-control metadata is retained, and one shared `VimMultiInsertPlan` exposes the complete batch and next session. Each member retains its own Replace stack and indentation state. A denied or otherwise ignored Backspace produces no edit for that member while valid members continue in the same atomic batch. Session offsets, replace frames and indentation spans are mapped through the prepared edit map with explicit anchor affinity. `mapVimMultiInsertSession` applies the same position transform to an external document change.

The planner accepts opaque UTF-8 paste bytes once, preserving terminal notation such as `<Esc>` as text. Newline and Unicode payloads broadcast to each member; active-line indentation is computed independently by the singleton planner. Escape converges all members to Normal only when every member exits together; mixed mode exits are rejected before publication. The implementation does not modify the shared Vim barrel.

## Failure cases and recovery

`T078-MC05-REPLACE-02/03/03A` demonstrates that a Backspace denied for one member leaves that member's state unchanged while another valid member's deletion is applied in the same prepared batch. `T078-MC05-MERGE-02/04/05` covers duplicate Insert carets and stable member convergence; `T078-MC05-MERGE-07` through `-12` cover cursor merge inside Replace, deduplicated restoration and stack convergence. `T078-MC05-PASTE-02` confirms terminal escape notation is opaque text. External edits are transformed with `T078-MC05-MAP-01/02/03`; no stale or partial multi-cursor state is published by the planner.
