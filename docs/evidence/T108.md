## Observable result

Production rope chunks now retain newline offsets in checked packed `Uint16Array`
indexes. The chunk cap makes the representation safe for all local offsets;
treap nodes aggregate index bytes without changing public UTF-16 coordinates or
persistent snapshot behavior. Public text-file EOL metadata remains owned by the
packed `LineEndingSequence` from T107.

## Performance and visual evidence

The two planning probes use the same generated 1 MiB dense LF bytes and retain
source SHA-256 `06dd1a4a771f4e3dbb1f255c4195c285fd51dfd6aa3c4862c545a64a9230c472`.
They are single shared-host diagnostics and do not establish PF01–PF06
distributions, native allocation provenance, UI output behavior, or a release
pass. Visual evidence is not applicable to this document-storage slice.

The private newline index is packed at two bytes per local break. Runtime
allocation totals remain unavailable on Bun 1.3.13; live heap, external/JSC,
native commit, process RSS and unsupported total-allocation fields are reported by
the T106 sampler where probes use it.

## Failure cases and recovery

The test rejects malformed UTF-16 and surrogate-split edits, preserves old roots
through edits and compaction, and checks packed index aggregates after mutation.
The pinned runtime cannot freeze typed-array elements, so the typed index is kept
private inside a frozen chunk; no public API exposes a writable view of it.
