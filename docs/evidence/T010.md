## Observable result

The primitives package exposes validated branded UTF-16 offsets, UTF-8 byte offsets, UTF-32 scalar offsets, line indexes and cell columns. Document snapshots provide versioned conversions between their safe UTF-16 boundaries and UTF-8/UTF-32 absolute offsets. `coordinates.ts` converts line/character protocol positions for UTF-8, UTF-16 and UTF-32, rejects stale versions and invalid boundaries, and caches each immutable snapshot's line-base offsets. Rope subtree aggregates make encoded-offset lookup bounded by tree height plus a scan of at most one 1,024-unit leaf. These positions count encoded units, not grapheme clusters. Terminal display-cell conversion remains owned by layout, where tab stops and terminal emoji-width policy are available.

`openTextDocument` strictly decodes UTF-8, extracts a leading UTF-8 BOM as metadata, normalizes configured line endings into logical LF text and retains each selected ending. Serialization reproduces BOM, mixed line endings and final-newline state exactly. The no-options path retains T010's legacy CRLF/CR/LF interpretation, and untagged inserted CR/CRLF normalizes to logical LF using the document's chosen default ending. Direct ordinary rope creation rejects CR; T101 adds an explicit literal-control intent and fileformat policy for CR content. Invalid UTF-8 and NUL-containing files remain read-only and return defensive copies of the original bytes.

## Failure cases and recovery

`T010-COORD-ROUNDTRIP-01` rejects invalid line and column positions, unknown encodings, stale versions, partial UTF-8 characters and UTF-16 surrogate midpoints. Malformed UTF-8 and NUL-containing byte inputs select the read-only path and preserve the exact original bytes. `T010-ROPE-EOL-01` ensures unnormalized CR cannot bypass EOL metadata through direct rope APIs; `T010-EDIT-EOL-01` verifies CR variants are normalized at the text-file boundary. The second U+FEFF sequence after a file BOM is preserved as ordinary content.
