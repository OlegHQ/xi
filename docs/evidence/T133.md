## Observable result

Production `runOpenTuiWorkbench` delegates frame coalescing, in-flight invalidations,
and backpressure retries to Core's public `requestRender`. The private `loop` cast,
method monkeypatch, microtask scheduler, frame-pending flag and 2 ms retry timer are
removed. `maxFps=1000` limits the configured throttle to 1 ms without starting a
continuous render loop. This is not a promise of 1 ms wall-clock scheduling.

A public pre-frame callback resolves viewport anchors and resets the old hardware
cursor. `onFrame` now follows Core's actual frame event, rather than assuming that
incrementing frameCount means painting has finished. It is still not physical-output
or photon evidence. Input normalization and ordered asynchronous dispatch are preserved.

Compared with the captured pre-change working files, terminal.ts goes from 1,530 to
1,456 lines and workbench.ts from 1,433 to 1,421 (obsolete scheduling comments removed).
Only this task's diffs are retained in `.artifacts/ui-declarative/*.ts.diff`; Git's full
diff also includes pre-existing changes and must not be attributed to this task.

## Performance and visual evidence

Three alternating-order baseline/candidate pairs ran the existing production-PTY
`bench/performance/t116-key-output.py` diagnostic, 30 events per process. Raw outputs,
all p50/p95/p99/max values and pair summaries are in `.artifacts/ui-declarative/`.

| Pair | Baseline p95 / max ms | Candidate p95 / max ms |
|---|---|---|
| 0 | 5.416 / 11.315 | 10.542 / 23.313 |
| 1 | 9.767 / 26.128 | 6.399 / 20.021 |
| 2 | 7.702 / 20.557 | 11.166 / 13.738 |

The mixed/noisy results do **not** establish non-regression or compliance with the
8 ms p95 budget. This acknowledged-input diagnostic times initial terminal bytes,
not a parsed correct frame; it is not the required open-loop workload matrix. The
earlier diagnostic run overlapped other checks and is retained, not used to claim
a speed improvement. No samples or outliers were removed.

The real xterm images were opened and inspected: the wide editor retained its text,
cursor, tab and status; the narrow image showed the existing compact sidebar/status
layout without corrupt cells. Exact edited file content survived resize and save.
