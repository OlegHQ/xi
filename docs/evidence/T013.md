## Observable result

`packages/vim/input` consumes the contracts package's canonical key, paste, focus and pointer events. It adds an injected monotonic timestamp, preserves event phase/modifiers, copies paste bytes defensively and does not inspect raw terminal bytes. The Vim parser returns distinct pending, command, consumed, cancelled, failed and unhandled outcomes. It keeps an immutable versioned `SelectionSetSnapshot` in parser session state, validates that its selection kind matches the mode, and attaches that snapshot to command intents.

The parser retains typed count, register, operator, command-prefix and literal-argument states. It distinguishes count-leading zero from the Normal `0` motion, keeps operator and motion counts separate, and explicitly saturates oversized counts at `Number.MAX_SAFE_INTEGER`. Parser states defensively copy and freeze nested count/operator records and continuation records/arrays; emitted operator intents own frozen operator/count copies as well. It emits typed mode-transition, search/Ex entry, motion, operator, text-object, literal-key, paste and Insert-key intents; it does not edit text or mutate registers/selections. `legalContinuations` exposes typed key, motion, count, register and literal-character metadata for the same state consumed by parsing.

The public Vim barrel re-exports the input and parser APIs. T013 adds no Neovim runtime dependency. The parser does not decode terminal bytes, maintain a writable document, or resolve/execute motion semantics.

## Failure cases and recovery

- `T013-CANCEL-FOCUS-01`: losing focus during `d` returns `cancelled` and clears the operator; the next `w` is parsed as a fresh command.
- `T013-ORACLE-ESCAPE-01` and `T013-ORACLE-ESCAPE-02`: the pinned oracle leaves text and the unnamed register unchanged after `d<Esc>` and `2d3<Esc>`. Xi parser tests verify the corresponding pending states cancel.
- `T013-CANCEL-INVALID-01` and `T013-ORACLE-INVALID-01`: an invalid control continuation after `d` becomes a typed failure in Xi; Neovim leaves text/registers unchanged and returns to Normal.
- `T013-GRAMMAR-COUNT-SATURATION-01` and `T013-ORACLE-COUNT-SATURATION-01`: forty `9` digits saturate to a safe integer in Xi. The pinned oracle accepts the huge count without an error and clamps the resulting motion at line end.
- `T013-INPUT-PASTE-ESC-01` and `T013-MODE-PASTE-01`: an opaque paste containing Escape-looking bytes and `q` remains one payload, including in Insert mode; those bytes cannot start Escape or macro grammar.
- `T013-SESSION-GENERATION-01/02`: an unchanged selection generation preserves pending grammar; a moved/replaced selection generation cancels it before the new session is installed.

## Limitations and next action

The pinned Neovim harness snapshots completed drained input but does not expose its internal pending operator/register/count state. The parser's incremental states are therefore asserted directly in Xi tests; oracle fixtures verify the resulting completed commands, cancellation, count and register behavior. The grammar emits intents and does not resolve motions, normalize ranges, commit edits, or implement mappings; those remain downstream engine work and no full-parity claim is made. The T006 production OpenTUI adapter remains owned by its later porting ticket; T013 consumes the shared canonical contracts and has no terminal decoder.
