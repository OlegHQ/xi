## Observable result

`WorkbenchRenderable` is a custom OpenTUI renderable that reads `WorkbenchReadPort` snapshots and projects visible rows through `ViewportLayout`. It stores no editable text, cursor, or selection copy. The shell provides the editor canvas, line gutter, sidebar, bottom panel, status row, primary/secondary selection markers, light theme tokens, and an ASCII fallback. `OpenTuiTerminalAdapter` and `runOpenTuiWorkbench` own renderer startup, resize, suspend/resume and cleanup. `bun run xi` now starts this shell in an alternate-screen terminal and exits cleanly on `q` or Ctrl-C.

The frame matrix is retained at [`.artifacts/ui/t034-frame-matrix.json`](../../.artifacts/ui/t034-frame-matrix.json) for 80x24, 120x40, 160x50, 240x70, 60x18 and 30x9. The real launch PTY transcript and status are [`.artifacts/editor/t034-launch.ansi`](../../.artifacts/editor/t034-launch.ansi) and [`.artifacts/editor/t034-launch.json`](../../.artifacts/editor/t034-launch.json).

## Layout and failure coverage

At 120x40 the sidebar is 30 cells and the editor retains 89 cells; at 160x50 and 240x70 it clamps to 40 cells. At 80x24 and 60x18 the sidebar is hidden, preserving the editor. At 30x9 the explicit “terminal too small” state retains the shell lifecycle. The layout projection handles Unicode width and places the primary cursor from the projected frame; secondary selections remain visible as distinct markers. ASCII mode replaces disclosure, status and cursor glyphs with width-one text.

`OpenTuiTerminalAdapter` leaves partial renderer creation owned by the caller's `DisposableScope`, reports typed startup/suspend/resume failures, and destroys the renderer exactly once. The virtual renderer test exercises resize and cleanup; the PTY launch exercises real terminal setup and restoration. The existing T002 renderer failure/backpressure evidence covers injected render failure behavior for the same pinned OpenTUI runtime.

## Limitations and next action

This is the first launchable editor surface, not the complete editor product. The launcher now adds the initial Vim Insert/motion/delete/save loop; picker/services, diagnostics, language actions, Git, persistence integration and full visual screenshot review remain downstream tickets. The available environment has no `xterm`, `xdotool` or ImageMagick binary, so this ticket retains OpenTUI cell captures and a real PTY transcript; cross-terminal screenshot review remains a later visual gate.
