## Observable result

`packages/vim/multi.ts` resolves one parsed motion, find or search command against one immutable document snapshot for every active member. It retains failed members for nonmutating commands, rejects mutating batches before publication, preserves each member's desired display column, supports ordinary, word and built-in text-object motions, extends character/line/block Visual members, and normalizes all operator edits into one versioned transaction. Search/find cancellation and stale selections return before selection publication. Shared search state, last-find state, marks and jumps are reduced once from the primary command; Visual shapes are keyed by stable member ID. MotionPreview is frozen presentation data carrying document and selection generations and is omitted when disabled.

## Performance and visual evidence

This ticket is a pure engine composition layer and has no render budget. Resolution reads the immutable document APIs and only scans ranges needed by each requested motion/search; it introduces no synchronous process or filesystem work and no Neovim runtime dependency. Render screenshots and terminal latency remain UI and qualification work in T034/T062/T087/T089.

## Failure cases and recovery

Overlapping pure deletes are unioned by the atomic edit normalizer; ambiguous replacement/insertion conflicts reject before publication. Invalid counts, missing find targets, stale document/selection generations and cancellation return typed failures with the original selection set intact. Mark and jump updates use the primary member once. Missing Visual history fails with the stable member ID instead of guessing.

## Limitations and next action

T077 does not claim a launchable UI, provider integration or final release qualification. Those are downstream T033 and T034 work. Singleton edge semantics remain owned and evidenced by T020/T021/T018; this ticket composes those public owners without duplicating their range or coordinate logic.
