## Observable result

`PersistenceService` opens files through the typed `FilesystemPort`, captures a content and platform identity, and delegates UTF-8/BOM/EOL/binary handling to the document owner. Invalid UTF-8, NUL-containing input and ambiguous line-ending input remain read-only with their original bytes retained. Save serializes one immutable document snapshot, verifies the captured disk identity, rejects symlink and multiply-linked inode replacement, writes through the platform atomic primitive, clears an existing recovery journal, and marks exactly the captured revision saved; edits made while the write is pending remain dirty. If journal cleanup is interrupted after the file write, the result reports that cleanup remains pending while preserving the clean document state.

Recovery checkpoints are versioned JSON records containing normalized document text, line-ending metadata, BOM state, revision/version identity and the base disk fingerprint. They are appended with bounded retention through `writeFileAtomic`. Restart restores a checkpoint only when its base disk identity still matches. A changed, replaced or newly created disk path returns `disk-diverged` with the recovered document for review and never writes over the disk. Session state has a separate validated schema and does not share the recovery text store.

`NodeFilesystemPort` supplies asynchronous read/stat/watch operations and same-directory temporary write/flush/rename with permission preservation. Symlinks are inspected with `lstat`; file and parent-directory flush failures are surfaced as typed platform failures.

## Performance and visual evidence

No visual surface or interactive keystroke budget is owned by T037. The save path hashes the existing target to detect same-size/coarse-mtime external edits; this is performed on the asynchronous persistence path and never on the ordinary keystroke path. Recovery journals retain at most 64 checkpoints and 16 MiB by default.

## Failure cases and recovery

- `T037-FAULT-01..03`: injected `ENOSPC` leaves the prior disk bytes, preserves the document's dirty state and retains the checkpoint for restart.
- `T037-FAIL-PERM-01..02`: injected `EACCES` is returned through `PersistenceFailure.platform` and does not clear modified state.
- `T037-FAIL-SYMLINK-01..02`: an identity change to a symlink is rejected as an external change; an opened symlink is rejected as `symlink-save` before atomic replacement.
- `T037-FAIL-HARDLINK-01`: `linkCount > 1` is rejected as `hardlink-save` so rename cannot silently break link identity.
- `T037-FAIL-RENAME-01..03`: a platform failure after replacing the target leaves the captured revision dirty; restart reports `disk-diverged` and leaves the new disk bytes untouched.
- `T037-DIVERGENCE-01..02`: external disk content after checkpoint produces a recoverable review result rather than an overwrite.
- Malformed recovery/session JSON is rejected by owner schema decoders; old journal bytes remain because writes use the platform atomic primitive.

## Limitations and next action

The platform contract exposes optional inode/device/link-count metadata; adapters that cannot provide it still receive content-hash and file-kind checks, while hardlink policy is enforced whenever link count is available.
