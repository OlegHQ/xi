## Observable result

`packages/ui/editor/motion-paint.ts` consumes a structural, immutable presentation read model for T077's versioned motion preview and optional exact operator preview. It validates document and selection generations against the published layout frame before painting. Paint is bounded to visible `ScreenRow.cells`; it skips gutters and padding while retaining full wide-glyph clusters and one explicit EOL cell. Layer precedence is base → motion trail → operator preview → secondary/primary Visual selection → secondary/primary cursor. Normal mode can show a static last-motion trail; Visual and Insert modes suppress it. No-color mode removes the decorative trail and uses reverse/underline attributes, while ANSI-256 mode uses deterministic palette quantization. `WorkbenchRenderable` keeps document and selection ownership in the workbench and exposes only paint statistics for test readback; no timer or continuous render loop is introduced.

The presentation read port is optional, so existing T034 composition remains compatible. A missing presentation or a `null` preview paints no trail. A stale document/version or selection generation rejects the preview for that frame, preventing old paint from resurfacing after an edit or selection transition. Cursor markers remain visible above all fills and primary identity wins at coincident projections.

## Performance and visual evidence

The painter visits only the published visible frame (`rows × cells`) and does not scan the document or semantic selection ranges. The reduced-motion fixture confirms one static paint and `hasScheduledRender === false` after `waitForVisualIdle`; no continuous animation loop exists. `.artifacts/ui/t087-paint.json` records visible-cell counts and cursor/layer readback for truecolor, off, ANSI-256, no-color, Visual, stale and narrow fixtures.

The retained xterm matrix covers the painter's truecolor, ANSI-256, no-color, Unicode and narrow-terminal paths. T063 remains responsible for the broader release visual cross-product (diagnostic overlays, focused/inactive views and the complete screenshot catalog); this ticket's painter-level visual gate is satisfied by the inspected captures and cell/style fixtures.

## Failure cases and recovery

- Trail mode `off` produces zero trail cells while exact operator preview remains independent.
- Visual and Insert modes suppress motion trail so it cannot be mistaken for a Visual range.
- A mismatched document ID/version or selection generation is rejected and reported in `MotionPaintStats.rejectedStalePreview`; the cursor and current selection remain painted.
- No-color mode disables decorative trail and preserves semantic distinctions through `INVERSE` and `UNDERLINE` attributes.
- Missing/cleared read models produce no trail and do not schedule a repaint.
- Renderer disposal destroys the workbench renderable through the existing T034 cleanup path.

## Limitations and next action

The painter does not own diagnostics, search overlays or inactive-view composition; those remain downstream UI work. Its visible paint, stale guards, fallback attributes and static scheduling are fully covered here, with broader release visual review owned by T063.
