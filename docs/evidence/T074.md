## Observable result

`packages/contracts` now exports inert, versioned command descriptors with stable namespaced IDs, argument/result decoders, selection/effect/undo/replay/cancellation policy, availability metadata and deterministic priority. Alias contributions refer to IDs or other aliases and cannot carry executable text. The `workbench` package owns an atomic registry through its public entrypoint. Registration validates candidate descriptors and the alias graph before publishing an immutable generation; command lists sort by priority and stable ID. A failed candidate leaves the previous snapshot object and handlers available.

Headless inspection and dispatch resolve the same descriptor and registration. Dispatch decodes unknown arguments and handler output, returns typed failures, captures its registry generation, and suppresses late output after caller cancellation or contribution disposal. Registration handles remove their complete contribution bundle and cancel its active invocations. The registry requires a nonempty native Ex name inventory and reserves each name plus its unambiguous abbreviations before accepting aliases.

## Failure cases and recovery

- Missing selection policy, duplicate command ID, alias cycle and collision with a native Ex abbreviation each reject the candidate; tests compare the published snapshot by object identity and then dispatch the last-good command successfully.
- Duplicate aliases are reported as ambiguous and do not change the published snapshot.
- Wrongly typed untrusted argument data returns `invalid-arguments`; the handler is not called.
- Disposing a contribution while its handler is pending cancels its token and makes dispatch return `cancelled` before the handler promise settles. A late handler result is ignored.
- Missing required capabilities return the descriptor's disabled reason and do not execute the handler.

## Limitations and next action

The collision API requires an authoritative native Ex name inventory from its caller and fails closed when the list is absent or empty. Tests use the focused `quit` inventory fixture; integration must pass the complete active profile inventory when the Ex compiler is introduced. `[EX01]` is covered at the registry/inspection/headless-dispatch seam only; palette, key, `:Xi`, and mouse routes await their UI/interaction owners. `[EX04]` covers stable IDs, availability and generation capture, not config migration or provider arbitration.
