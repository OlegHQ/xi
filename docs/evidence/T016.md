## Observable result

`packages/vim/motions/index.ts` provides a read-only, version-bound resolver for horizontal, line-boundary, vertical, linewise, and file-line motions. It handles counts, sticky desired display columns, tabs, grapheme boundaries, `whichwrap`, and `startofline`; failures return typed errors. Motion resolution does not mutate the document. The committed oracle corpus has 21 fixtures and 107 snapshots, including `T016-ORACLE-GRAPHEME-MOTION-01` (Neovim skips the combining scalar as a separate cursor stop) and `T016-ORACLE-TAB-CHAR-MOTION-01` (a cursor on a tab desires its final occupied display cell).

The `T016-ORACLE-MOTION-STATE-INVARIANTS-01` trace seeds registers with a yank, then runs only `0`, `j`, `$`, `G`, and `gg`. Both the oracle validation and the resolver test compare every subsequent text snapshot and every captured nonempty register against the post-yank snapshot. The resolver test also confirms the Xi document version and full text remain unchanged. Error cases cover stale document versions, zero/unsafe counts, and an initial cursor inside a combining grapheme.

## Performance and visual evidence

The reproducible resolver microbenchmark is [`T016-motion-benchmark.json`](T016-motion-benchmark.json), produced by `bun run tests/vim/motions/t016.bench.ts`. It uses 10 warmups, then 100 samples for the ordinary-source and ASCII cases and 15 samples for each special-path probe. The 2,000-line small-source `h` measured p95 0.0147 ms against the 1 ms engine-step target. On a 100,000 UTF-16-unit line, ASCII `h`, `l`, and `$` measured p95 0.0034, 0.0328, and 0.0164 ms. On a 1 MiB ASCII line, `l` and `$` measured p95 0.0197 and 0.0166 ms against the 16 ms large-file typing target. The 100k tab, combining, and wide-character neighbor probes measured p95 0.0268, 0.0491, and 0.0651 ms.

The wrapped-left case is now served by the bounded line-edge path: from line 2, column 0, `h` with `whichWrap=h` measured 0.0125 ms p95 across 15 samples after warmup, within the 1 ms resolver target. The fast path caches printable-ASCII line edges by immutable snapshot identity without retaining closed snapshots. T062 must still measure the full input-to-output boundary, loaded services, CPU/GC traces and native comparison; this resolver-only benchmark does not establish a full release performance pass.

An earlier one-off 100k-line probe, before the bounded paths, measured cursor creation at 57.42 ms, `h` at 45.565 ms, and `$` at 75.464 ms. Those were single observations, not the standardized sample set above, so they are indicative only and not a statistically comparable baseline. Cursor construction is excluded from the current timed resolver loop. No visual evidence applies to this non-rendering module.

## Failure cases and recovery

`T016-MOTION-NEGATIVE-01` rejects a stale cursor/document version; `T016-MOTION-NEGATIVE-02` and `-03` reject zero and unsafe counts; `T016-MOTION-NEGATIVE-04` rejects a cursor inside a grapheme. These return errors without changing the document. Horizontal/file boundary, empty document, count-over-EOF, sticky-EOL, `whichwrap`, tab, ragged-line, and motion-only text/register cases are covered by the pinned fixture IDs listed in `tests/vim/motions/fixtures.json`.
