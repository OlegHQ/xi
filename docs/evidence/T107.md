## Observable result

`LineEndingSequence` now persists fixed 8,192-break blocks in an immutable implicit treap. A uniform block stores one ending code; a mixed block stores four 2-bit ending codes per byte. Split and splice operations copy only touched blocks and treap paths, so retained snapshots continue to reference their original metadata. Normalization uses a packed builder and a fast all-LF path instead of allocating one string/array entry per newline. `TextFileDocument.lineEndingStorageMetrics()` exposes immutable accounting counters for diagnostics without exposing writable storage.

The public `TextFileSnapshot.lineEndings` contract is unchanged. It materializes the requested compatibility array lazily; opening and editing a document do not request that array.

## Performance and storage evidence

The earlier diagnostic public 1 MiB dense LF run recorded approximately 1,500.08 ms open, 137.12 MiB reported heap growth and 248.22 MiB RSS growth in the performance-planning reproduction. The current-tree packed run above recorded 256.608 ms open, 19.46 MiB retained heap growth and 56.25 MiB RSS growth. These are separate diagnostic processes on a shared host, so they show the direction and density remediation but are not a controlled release comparison.

T106 still reports zero observed current-catalog cells, so this diagnostic cannot be imported as a qualified production observation.

## Failure cases and recovery

The new fixture exercises a splice through the packed block boundary, holds the old snapshot, serializes it after the edit, then undoes and serializes the current document. Existing T010 and T012 fixtures cover deletion/insertion of mixed endings, history replay, compaction, BOM, literal CR and rejected bytes. No block is recycled or mutated after publication.

## Limitations and next action

1. T106 is still in progress: no compatible 30-trial baseline/candidate pair, dedicated reference host, or complete production performance adapter exists.
2. T107 does not yet have the required public open/commit CPU distributions or full PF03 allocator/native/worker attribution. The probes retain signed Bun/JSC/process deltas, while total allocation and document wrapper counters remain unsupported by the pinned runtime/API.
3. The 10 MiB public RSS/heap result remains high because `RopeDocument` still retains a JavaScript number per line break. T108 owns packed rope indexes and the full PF01–PF06 requalification.

The next performance action is T108 after T106 and T107 have completed their evidence gates; no ticket is marked done by this report.
