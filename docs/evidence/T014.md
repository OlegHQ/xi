## Observable result

`ViewportLayout.project` maps immutable document and selection snapshots into bounded terminal rows, projected endpoints, and a versioned frame/hit map. It owns no text, editing state, or OpenTUI objects. The public contract uses branded document, view, selection, generation, UTF-16 offset, line, and cell types. It handles wrapping, tab stops and virtual tab cells, grapheme and wide-cell projection, horizontal clipping, folds, resize anchors, block-cell endpoints, and clipped selections. Stale versions and malformed folds are rejected before publishing a frame.

Line layouts are cached by visible text and layout policy, and materialized rows by line identity/geometry. A text edit changes only the affected content key; frame identities retain the current document version. Caches and visible text reads are bounded, and `dispose()` clears retained projections.

## Performance and visual evidence

The benchmark measures the layout projection call only. Percentiles are milliseconds on the Linux aarch64 host above:

| Workload | p50 | p95 | p99 | max |
|---|---:|---:|---:|---:|
| Repeated identical frame (cache hit) | 0.0020 | 0.0042 | 0.0084 | 0.0259 |
| Alternating viewport anchors at lines 500 and 5,000 | 0.7443 | 2.4384 | 3.0832 | 3.7752 |
| One committed same-length edit per sample with unique changed-line content, new document version, visible frame rebuilt | 1.0756 | 2.3685 | 3.4260 | 4.0297 |

Across the run, cache counters reported 329 frame hits, 25,990 line-layout hits, 450 line-layout misses, zero line-layout evictions, 25,990 materialized-line hits, 450 materialized-line misses, 117 materialized-line evictions, 450 rows built, and 450 retained line layouts. The edit workload commits the edit and maps the selection before timing `project`; it uses a unique same-length prefix each iteration so changed-line geometry is rebuilt rather than served by a previously warmed text key. Its timing isolates the layout portion of a changed-version frame.


An independent reviewer reran `bun run bench/layout/t014-viewport.ts` on 2026-09-14 against the T014 acceptance snapshot. Its one-line edit/new-version workload measured p50 1.1644 ms, p95 2.8594 ms, p99 5.4473 ms and max 10.9960 ms, with 450 changed-line misses and 117 cache evictions. The benchmark output was retained in the command log; this measures pure layout rather than the integrated render/output path.

Before T085's collision-safe cache-key follow-up, an independent reviewer repeated the benchmark four times on 2026-09-14 (one run alongside repository checks, then three sequential runs). Each used the same 10,000-line, 120×40 corpus with 300 measured samples. Across those prior-source runs, changed-viewport p95 ranged from 2.2806 to 3.8863 ms; one-line-edit/new-version p95 ranged from 2.4555 to 3.2950 ms. p99 reached 7.3514 ms for viewport changes and 5.8857 ms for edits; observed maxima reached 10.9979 ms and 6.1261 ms, respectively. These remain layout-only figures; the integrated render/output target is unproven.

After the collision-safe geometry, projection, line-layout and materialized-row cache keys landed, the benchmark was rerun twice sequentially against the current source on 2026-09-14. Each run used the same pure-layout corpus with 300 measured samples. Changed-viewport p95 ranged from 2.1646 to 2.2274 ms (p99 3.4996–3.9837 ms, max 6.1488–7.0547 ms); one-line-edit/new-version p95 ranged from 2.2953 to 2.3860 ms (p99 3.4584–3.5791 ms, max 3.8077–4.0454 ms). This benchmark does not measure styling, rasterization or terminal output.

This result does **not** establish the plan's 120×40 render target of p95 ≤ 4 ms: that target includes layout, styling, rasterization, and output enqueue, while this benchmark stops at pure layout. There is no rendered application frame to inspect yet, so screenshot, PTY, and terminal-output evidence are not applicable to this package ticket.

## Failure cases and recovery

- `T014-WIDE-EDGE-01`: a wide glyph that would straddle the no-wrap viewport edge becomes a blank clipped cell; its hit target still maps to the glyph's UTF-16 start boundary.
- `T014-TAB-WRAP-01`: a tab keeps its logical tab stop across wrapping and exposes distinct virtual-cell targets before and after the wrap.
- `T014-FOLD-CURSOR-01`: a selection endpoint inside a visible fold projects to its header placeholder.
- `T014-STALE-HIT-01`: after resize publishes a new layout generation, hit testing against the old frame is rejected as stale.
- `T014-INPUT-VALIDATION-01`: stale snapshot versions and overlapping folds fail without publishing a frame.
- `T014-BOUNDED-INVALIDATION-01`: a one-line edit produces one changed-line layout miss while three unchanged line layouts hit the cache.

The projector is synchronous and pure, so it retains no task or external handle to cancel. `dispose()` clears frame history and both layout caches.
