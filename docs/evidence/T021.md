## Observable result

Visual selection state is represented through the shared selection owner. The Vim Visual planner supports character, line and block selection state, endpoint exchange (`o`/block `O`), and replay of the prior selection (`gv` including the observed count behavior). Parser transitions cover `gh`, `gH`, `g<C-h>`, and Ctrl-G switching between matching Visual and Select modes. Select typing produces a versioned pure replacement proposal. Visual change planning produces typed row-wise document edits; the document remains the mutable text owner.

Pinned comparisons validate selection kind and active cursor/desired-column state, operator register payload/type/width, and resulting or unchanged text. Block change preserves unselected cells on either side of a partial tab, including the minimized `A\tB` rectangle that crosses both a normal grapheme and a partial tab. T021 also keeps visual block tab preservation separate from the operator-pending default so existing T019 delete/change behavior remains intact.

## Performance and visual evidence

T021 defines no latency threshold and does not render UI. This ticket prepares versioned edits through the document boundary and does not claim an interactive rendering or launch-readiness pass.

## Failure cases and recovery

The listed cases are pinned and exercised: partial-tab delete/change (`T021-ORACLE-BLOCK-PARTIAL-TAB-DELETE-01`, `T021-ORACLE-BLOCK-CHANGE-TAB-01`, and `T021-ORACLE-BLOCK-CHANGE-TAB-EDGE-01`), the wide-glyph boundary (`T021-ORACLE-BLOCK-WIDE-GLYPH-EDGE-01`), and an empty selected final line (`T021-ORACLE-LINE-EMPTY-LAST-01`). Ragged block boundaries and resulting register geometry are covered by `T021-ORACLE-BLOCK-RAGGED-01` and `T021-ORACLE-BLOCK-DELETE-BOUNDARIES-01`. Typed failures reject stale document versions, nonpositive `gv` counts, block-column exchange on non-block selections, and invalid UTF-16 replacement text without planning an edit.
