## Observable result

The language service decodes versioned and unversioned LSP workspace edits into
validated UTF-16 absolute ranges. The workbench coordinator rejects stale
versions, invalid ranges, overlaps and resource collisions before mutation.
Open dirty buffers and closed files are resolved separately: open buffers keep
their in-memory version and closed files are read, hashed, revalidated and
atomically saved.

Resource operations validate workspace containment and permissions, support
create/delete options, resolve rename chains and cycles through ordered native
renames, and update an open buffer's path after a successful rename. Optional
`workspace/will*Files` and `workspace/did*Files` hooks participate around the
coordinated operation when the server advertises them.

Code actions preserve disabled reasons, lazy resolve data, edits, annotations
and commands. The selected action applies its edit before executing its command;
unsupported commands produce explicit feedback after any successful edit.

## Performance and visual evidence

Workspace requests and file operations are off the ordinary key path. Resource
validation is bounded by the proposal's documents and operations; the edit
coordinator performs one preflight and one apply. No standalone visual surface
was introduced. Numeric loaded-input, allocation, retention and reference-host
qualification remain unproven under T106 and T107–T118/T115.

## Failure cases and recovery

- `T052-STALE-01` and the dirty E08 fixture reject stale document versions or
  changed closed-file hashes before applying the proposal.
- `T052-OVERLAP-01` rejects overlapping edits before the port is called.
- `T052-COLLISION-01` rejects duplicate resource destinations.
- `T052-CHAIN-01` admits a rename chain; the production resource executor moves
  the tail first and uses a unique temporary path for cycles.
- Server workspace edits outside the admitted workspace resolve to a typed
  stale failure and cannot reach filesystem mutation.
- Unsupported language commands are reported after the edit step and are not
  falsely reported as executed.
