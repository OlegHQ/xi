## Observable result

`JournaledFilesystemOperations` preflights every source and destination against an asynchronous injected platform, fingerprints file content and platform identity, rejects destinations created outside the reviewed plan, and runs directory drafts through a durable per-step journal. Rename plans stage every source under an operation-specific temporary name before committing destinations, which handles rename cycles and case-only changes. Cross-device rename reports `EXDEV` and falls back to verified copy/delete. Copies are verified against the reviewed source; deletes move into Xi recovery storage rather than silently discarding bytes.

Each completed step is flushed through the platform atomic-write primitive. A partial journal preserves completed steps and supports restart-safe `retry()`/`retryJournal()`. `restoreApplied()`/`restoreJournal()` recheck fingerprints before reversing steps and stop on external changes without overwriting them. Draft `DirectoryDraft.undo()` remains an in-memory plan operation and is separate from applied-operation restore. `will`/`did` hooks provide the typed pre/post boundary for LSP file-operation integration.

`NodeFilesystemPort` now supplies asynchronous mkdir, rename, copy and remove primitives. Copy preserves symlinks through the native platform adapter; removal is recursive only for directory steps and cancellation is checked before and after each platform call.

## Failure cases and recovery

- `T042-CYCLE-01..08`: the two-way rename cycle is staged through operation-specific temporary paths, exact bytes are swapped, and the durable journal restores both original paths.
- `T042-CASE-01..05`: case-only rename passes through a temporary path and produces the exact destination bytes.
- `T042-PARTIAL-01..07`: injected `EXDEV` plus source-delete failure leaves both source and verified staged copy, records a partial journal, and retry reconciles the copy/delete step without data loss.
- `T042-EXTERNAL-01..07`: a destination created by the preflight hook stops execution; restore returns completed staged work while preserving the unrelated external destination byte-for-byte.
- `T042-TRASH-01..07`: trash moves bytes to Xi recovery storage; applied restore returns the deleted entry and removes the applied copy. Draft undo is tested independently and never calls the filesystem.
