## Observable result

`WorkspaceReplaceService` builds replacement edits from the exact search ranges/query dialect, supports multiline and zero-width ranges, expands numeric and named captures, and accepts preserve-case only through the explicit `\\L`, `\\U`, `\\E`, `\\l` and `\\u` grammar. It rejects stale generations, changed source identity, duplicate/overlapping edits and invalid replacement syntax before mutation. The launcher binds the port to dirty document transactions and closed-file atomic writes and retains a journal that can restore applied entries after revalidation.

## Performance and visual evidence

Plans are linear in selected matches plus the target text scan and apply only after all targets are revalidated. The production PTY path exercises the same OpenTUI search surface; replacement input is a small state within that overlay, so no extra renderable was introduced.

## Failure cases and recovery

Changed text/hash/version refuses blind apply. Invalid regex, malformed replacement, missing targets and overlap leave the prior content untouched. A failure after earlier files have applied returns a partial journal with the completed entries and failed path; `restore` rechecks each after-image and refuses to overwrite later external changes.

## Limitations and next action

The journal is returned to the composition root and is currently process-scoped; durable restart discovery and the complete E06 fault matrix remain T065/T073 qualification work. Search remains a labeled ripgrep dialect, while Vim substitution remains owned by the Vim pattern engine.
