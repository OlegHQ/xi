## Observable result

`WorkbenchSession` owns the buffer registry, visible views, split tree, active focus and viewport positions. Each buffer owns one `TextFileDocument` and one `AtomicCommandCoordinator`; views in a split append immutable per-view engine state to that coordinator, so edits and the document undo tree are shared while selections and focus remain independent. Document change subscriptions map every live selection set through the committed change map, including edits and undo performed through the document boundary.

Preview buffers have a named slot. A clean, unpinned preview is replaced by the next preview; a dirty preview returns `dirty-preview-replacement` and remains open. Explicit pinning and the first successful text edit promote a preview. Closing a dirty buffer returns Save/Keep open/Discard choices; cancel and Keep open retain the document and active focus, while Discard removes only the requested view or buffer. Async close methods allow the injected save hook to complete before close.

Split geometry is immutable at the read boundary and has a configurable minimum pane size. Resize rejects a ratio that would make either pane smaller than the minimum. Layout persistence serializes workspace identity, buffer paths/flags, visible split structure and per-view scroll state without serializing recovery text or replacing document contents. Unknown layout fields, malformed identities, invalid ratios and missing restored buffers/views are rejected before state mutation.

## Failure cases and recovery

- `T038-DIRTY-PREVIEW-01`: replacing an already dirty preview returns `dirty-preview-replacement`; the old buffer, text and view remain present.
- `T038-MISSING-RESTORE-01`: a layout referencing an unavailable buffer returns `missing-restored-buffer` before changing open buffers or content.
- `T038-SPLIT-MIN-01`: a 60-cell split at ratio 0.9 rejects the 54/6 geometry with `split-too-small` and leaves the prior ratio installed.
- E02 cancel leaves the dirty shared buffer open and focusable; a later explicit discard removes only the selected split view and preserves the source content.
- External committed changes and shared undo map each live view through one versioned change map; stale selection versions are never silently reused.

## 2026-09-17 addendum: bare 'q' silently discarded unsaved edits — found and fixed

Discovered while investigating T130 (dot-repeat/macro wiring): Xi's documented quick-quit shortcut (the placeholder buffer text literally reads `// Press q or Ctrl-C to quit`) let a single, extremely common Normal-mode keystroke silently destroy unsaved work with no warning, unlike `:q`, which already refuses on a dirty buffer (proven in `docs/evidence/T064.md`'s "dirty :q refusal").

**Root cause.** `packages/workbench/vim-session/index.ts`'s key handler had `if (mode === 'normal' && key === 'q') return false;` — an unconditional `false`, never consulting document-dirty state. `packages/ui/src/terminal.ts`'s `finishApplicationKey` then unconditionally destroyed the renderer whenever the unhandled key was literally `'q'`, regardless of mode-check context. Reproduced with a real production PTY: opening a file, typing an insert (`iXXX<Esc>`, leaving the buffer dirty and unsaved) and pressing bare `q` exited the process cleanly with the typed text never written to disk — confirmed twice, byte-exact, before the fix.

**Fix.** Changed the vim-session handler to `return submitCommandLine('q');` — routing bare `'q'` through the exact same Ex-command path `:q` already uses (`handleWorkbenchCommand`'s dirty check, and `executeExCommand`'s `unsaved changes (use :q! or :wq)` refusal), instead of bypassing it. A dirty buffer now shows the identical refusal message `:q` gives and the process stays open with the edit intact; a clean buffer still quits immediately exactly as before, so the documented shortcut's behavior is unchanged for its common case.

**Regression fallout, found and fixed.** The prior unconditional-quit behavior had become a widely relied-upon test-teardown convention across the existing suite (dozens of PTY fixtures send a bare `q` at teardown). Running the fix against the full suite surfaced exactly the cases where a fixture pressed bare `q` on a *dirty, unsaved* buffer expecting the old destroy-anyway behavior:
- `tests/e2e/t051-completion-pty.py`, `tests/e2e/t088-language-edits-pty.py`, `tests/e2e/t088-primary-only-pty.py`: each applies a completion (leaving the buffer dirty) then quit with bare `q`. Fixed by quitting via `:q!` explicitly (the scratch edit was never meant to be preserved).
- `tests/e2e/t055-formatting-pty.py`'s failure-path case: a failed format-on-save intentionally leaves the buffer dirty on disk-mismatch; fixed the same way.
- `tests/e2e/t071-native-navigation-pty.py`: `gf`/`Ctrl-W gf`/tag-jump can leave more than one view open, and each `:q`/bare-`q` now correctly closes one view at a time (matching real multi-window `:q` semantics) instead of the old behavior's incidental one-shot destroy of the whole process regardless of view count. Fixed by looping `:q!` until the process actually exits, instead of assuming a fixed view count from stray Normal-mode keystrokes.
- Every other fixture using bare `q` (roughly two dozen across `tests/e2e/` and `tests/distribution/`) was individually confirmed to quit on an already-clean buffer and needed no change.
