## Observable result

`normalizeVimOperatorRange` centralizes characterwise inclusive/exclusive, linewise, and blockwise range conversion. `prepareVimOperator` produces versioned document edit plans, register effects, cursor intent, next mode, and repeat state for delete, change, and yank without publishing document or register mutations. The acceptance harness compares the prepared text, cursor, mode, register payload/type/destination, and transaction boundary with pinned Neovim snapshots. Changes and deletes preserve the document layer as the mutable text owner; the consumer remains responsible for committing the edit plan and applying register effects.

The 23 pinned fixtures cover count multiplication (`2d3w`), counted doubled operators (`2dd`, `2cc`, `2yy`), `d0`, `d$`, backward `db`/`dge`, exclusive next-line column zero, indented EOF, empty final-line deletion, forced characterwise/linewise/blockwise ranges, block selections crossing tabs and wide graphemes, `cw`/counted `cw`/cross-line `cw`, `cc`/counted `cc`, yank register behavior, and failed-motion repeat-state preservation. The oracle test verifies 23 fixtures / 25 snapshots; the operator acceptance test compares 22 successful operator plans and separately exercises the failed-motion fixture. Delete/yank cursor boundaries are compared after applying the plan; `cw`, counted/cross-line `cw`, and single/counted `cc` compare their planned insert gaps against the pinned trace-derived expectations.

## Failure cases and recovery

The listed failure cases are exercised by `t019.test.ts`: exclusive motion endpoints at next-line column zero (`T019-ORACLE-EXCLUSIVE-NEXT-LINE-COLUMN-ZERO-01` and `T019-ORACLE-CW-NEXT-LINE-COLUMN-ZERO-01`), deletion of an empty last line (`T019-ORACLE-EMPTY-LAST-LINE-DELETE-01`), forced range kinds (`T019-ORACLE-FORCED-CHARWISE-01`, `T019-ORACLE-FORCED-LINEWISE-01`, and the `T019-ORACLE-FORCED-BLOCKWISE-*` fixtures), and failed motion followed by repeat (`T019-ORACLE-FAILED-MOTION-REPEAT-01`). Failed motion produces no transaction or register effect and preserves the exact prior operator state/repeat target.

## Limitations and next action

All acceptance items listed for T019 are covered by the passing focused differential tests. The fixtures establish only the enumerated Neovim 0.12.4 behaviors; they do not claim complete Vim parity for untested options or every block/tab edge. This ticket prepares effects but does not integrate a full command dispatcher, commit transactions, publish register changes, or validate a launchable TUI. Those remain separate integration and release gates. No T019-listed acceptance item is known to remain unmet; review and ledger status are owned by the parent agent.
