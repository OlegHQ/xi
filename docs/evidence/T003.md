## Observable result

The oracle installer fetches one versioned Linux ARM64 release asset and verifies its archive hash before extracting it under ignored `.artifacts/oracle/`. Every fixture run checks the executable hash, complete `--version` output, runtime-doc count and aggregate hash, plus critical help-file hashes. Neovim runs with `--clean -u NONE -i NONE --noplugin`, `VIMINIT`/`EXINIT` cleared, a temporary `HOME`, separate XDG roots, `C.UTF-8`, UTF-8 text, Unix EOL and single-width ambiguous characters. The personal Neovim configuration is not read or executed.

The headless oracle feeds termcode-expanded keys as typed input with mappings enabled. `feedkeys(..., 'xt')` is the documented drain barrier; the snapshot records buffer text/EOL, byte-based cursor and virtual columns, mode/pending state, view and geometry, relevant options, registers, marks, jump/change lists, search state and errors. A separate OS PTY harness sends real terminal bytes to Neovim at fixed rows/columns, captures screen position and retains the terminal stream while checking alternate-screen/cursor restoration.

The generated [compatibility inventory](../compatibility/neovim-0.12.4.json) has 597 rows from the pinned Insert, Normal, operator-pending and Visual indexes. Rows record help tags, keys, modes, candidate options, dependency candidates/review state, fixture IDs, an implementation/audit ticket and `unimplemented` status. Text objects are represented in both operator-pending and Visual modes. The inventory is a seed for later implementation; none of its rows claims verified parity.

## Performance and visual evidence

No Xi interaction performance claim is applicable to an oracle-only ticket. The true-PTY fixtures establish Neovim's fixed terminal geometry and cursor/screen row; raw ANSI transcripts are retained under `.artifacts/oracle/pty/` for reproduction. They do not qualify Xi rendering or performance.

## Failure cases and recovery

- `ORC-MISSING-01` — Missing oracle: `verifyOracleBundle()` and the `XI_NVIM` override reject a nonexistent executable.
- `ORC-BARRIER-01` — Buffered input not yet processed: the first state is captured before drain; the next state after the barrier proves processing order.
- `ORC-MANIFEST-MISMATCH-01` — Version/docs mismatch: separate version-output and runtime-doc hash checks reject deliberately stale metadata. The exact pinned bundle also checks executable, runtime-doc tree and critical files before every run.
- `ORC-MUTATION-RANGE-01` and `ORC-MUTATION-BYTE-01` — Deliberate candidate mutations fail the differential comparator at the expected fields.
- `ORC-MINIMIZE-RANGE-01` — The mismatch-preserving reducer produces `dw` as the minimized key sequence.

## Limitations and next action

- The pinned download currently targets Linux ARM64, matching the validated toolchain environment. Other OS/architectures need their own versioned asset hashes before they can run this oracle.
