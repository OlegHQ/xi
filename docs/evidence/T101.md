## Observable result

`DocumentEdit.textIntent?: 'literal-control'` lets the document owner distinguish a literal U+000D from line-ending input. Tagged text retains CR; untagged CR and CRLF continue to normalize to logical LF. Rope mutation accepts CR only with the tag, while a separate initial-content constructor is used after an explicit open policy classifies CR as content. Change validation, previews, anchor mapping and serialized undo edits preserve this tag; undo and redo therefore restore literal CR without changing LF line boundaries.

`openTextDocument` accepts `fileFormat: 'unix' | 'dos' | 'mac' | 'auto' | 'legacy'`. Unix treats CR as content, dos recognizes CRLF and leaves lone CR as content, mac recognizes lone CR as an ending, and strict auto returns a typed `ambiguous-line-endings` read-only document for lone CR bytes while retaining an exact defensive copy. Existing no-options calls retain T010's previous mixed-ending interpretation (`legacy`) for compatibility. A live NUL remains editable and serializable; raw NUL-containing files remain lossless and read-only under T010's binary-input policy.

## Performance and visual evidence

No separate performance threshold or visual output is assigned to this document API ticket. The edit path transforms only the supplied edits and line-ending metadata; this change does not add a whole-document scan to keystroke processing. No renderer or UI was changed.

## Failure cases and recovery

`T101-FILEFORMAT-01` distinguishes a final literal CR from a trailing legacy CR line ending: strict auto keeps the original bytes read-only, explicit Unix opens the CR as content without a final newline, and explicit Mac opens it as a final line ending; both editable choices serialize to the original bytes. `T101-LITERAL-CR-01` covers literal CR beside mixed CRLF endings, line indexing, anchors and persisted undo/redo. `T010-EDIT-EOL-01` covers both generic CR and CRLF payload normalization. `T101-LEGACY-NUL-01` and `T010-RAW-BYTES-01` cover live NUL edits and lossless read-only raw-NUL reopen. Shared validation exposed a T031 import cycle and later strict typing errors in its viewport test during parallel edits; both were fixed, and the final `bun run check` passed.

## Limitations and next action

All T101 acceptance items pass. The no-options open API intentionally remains on the legacy T010 policy; callers that need to distinguish literal CR from Mac line endings must pass a fileformat explicitly or choose strict auto and handle its typed read-only ambiguity result. The workbench has no fileformat preference UI yet. T022 can now integrate `textIntent: 'literal-control'` for its pinned CR digraph fixture and rerun its full Insert/Replace matrix; its NU/LF cases already match the pinned live-buffer observation.
