## Observable result

`resolveVimFind` is exported through `packages/vim/src/index.ts`. It resolves counted `f`, `F`, `t`, `T`, `;`, and `,` motions against the current versioned document snapshot without editing text. Direct failed finds retain the attempted key and target as the new repeat state, matching the observed Neovim behavior. Subsequent `;` and `,` use that failed target. Till repeats retain the last matched location and its document/version identity so they skip the character already passed by the cursor; a stale or cross-document match location is not used.

No-match results preserve the cursor and report the context recovery needed by the owner: Normal is a no-op, operator-pending cancels the operator, and Visual preserves the selection. T018 tests compare the resolver's cursor and desired display column with Neovim, then separately compare exact Neovim document, cursor, registers, marks/selection, mode, and error snapshots around Normal, operator, and Visual failures.

The oracle probe recursively sorts JSON object keys before writing its trace. Repeated Neovim RPC captures previously produced the same snapshot values with different object-property order, which changed the artifact hash. After canonicalization, two sequential probe runs produced byte-identical trace SHA-256 `00bd818e0d0da3cde17fa1ca82893ce4d328b83d3fe14865275617672400d5d0`.

## Performance and visual evidence

No dedicated performance threshold or visual-rendering acceptance applies to this pure motion resolver. It searches only the current logical line and uses grapheme boundaries; this ticket did not run a full input-to-output latency benchmark or UI visual test.

## Failure cases and recovery

- `T018-FIND-MISSING-STATE-01`: after a successful `fX`, missing `fZ` leaves the document/cursor/register/selection state unchanged. Later `;` and `,` remain no-ops because the new repeat target is `Z`, even though `X` exists both before and after the cursor. The resolver reports `lastFind.target === "Z"`.
- `T018-FIND-OPERATOR-FAILURE-01`: failed `dfZ` leaves text, cursor, registers, and marks unchanged and exits operator-pending mode. Following `;` and `,` remain no-ops on the remembered `Z` target. Resolver recovery is `cancel-operator`.
- `T018-FIND-VISUAL-FAILURE-01`: failed Visual `fZ`, `;`, and `,` preserve the exact text, cursor, registers, marks, and Visual mode. Resolver recovery is `preserve-visual-selection`.
- `T018-FIND-ADJACENT-OPERATOR-01`: `tb` with adjacent `b` resolves to the current grapheme without cursor movement; Neovim's `dtb` deletes that character, so the endpoint remains operator-inclusive.
- `T018-FIND-REPEAT-DIRECTION-01`: `;` repeats the original till/find direction after `,`; counted `2,` and the subsequent `;` match the pinned cursor positions.
- Unicode: composed `é`, plain base `e` against a decomposed grapheme, precomposed `é`, and supplementary `😀` target/count cases compare with Neovim.

## Limitations and next action

- The initial raw-oracle corruption was fixed under T099. The retained `T018-HARNESS-RAW-SUPPLEMENTARY-REPRO-01` now checks that `keys: "f😀"` preserves `a😀b😀c`, leaves registers equal to the pre-input snapshot, and moves to the first emoji at byte column 2. T099 additionally covers raw insert input, mappings, barriers, ANSI-styled PTY output, and terminal restoration.
- The probe's JSON key-order instability was reproduced, fixed by recursively sorting keys, and verified with two byte-identical sequential captures; the recorded trace hash is stable for this pinned environment.
- The public barrel exposes the resolver, and its module-level failure outcomes are tested. A complete parser/operator engine dispatch and UI interaction were not exercised in this ticket evidence; the owning integration path must consume `cancel-operator` and `preserve-visual-selection` as specified.
- The compatibility artifact is ticket-scoped fixture evidence, not a claim that the full Neovim help inventory has been audited or updated. T061 owns that inventory reconciliation.
