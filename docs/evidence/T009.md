## Observable result

`RopeDocument` stores persistent, surrogate-safe text leaves capped at 1,024 UTF-16 code units. Treap aggregates provide UTF-16 length, UTF-8 byte length, UTF-32 scalar length, LF count, chunk count, height and maximum chunk size. The UTF-8/UTF-32 aggregates support bounded coordinate conversion in T010. Version-checked single and batch edits, slices, line lookup, immutable snapshots and snapshot-preserving compaction are exposed through the document package. Ordinary raw-rope creation and untagged text-file edits retain LF-normalized behavior; T101 adds an explicit tagged edit/constructor path for literal CR content without changing the storage or line-break aggregates. Hot-path range validation creates no success objects; compaction changes storage only and does not change the logical version.

The hashed T009 source manifest contains `packages/document/src/contracts.ts`, `packages/document/src/index.ts`, `packages/document/src/rope.ts`, `tests/document/verify.ts`, `bench/document/t009-storage.ts` and `bench/document/t009-fragmentation-probe.ts`. The T011 owner-boundary work keeps `RopeDocument` internal to the document package; the public barrel exposes versioned text-file transactions instead of the raw mutable storage object.

## Performance and visual evidence

For the 100,000-edit fixture, per-operation latency was p50 11.166 µs, p95 20.625 µs, p99 52.208 µs, and max 4,116.62 µs. This is a document-storage trace, not an end-to-end editor latency claim. The process-RSS result is 27,885,568 bytes below its limit. No visual evidence applies.

## Failure cases and recovery

The initial isolated memory probe exceeded the RSS limit by 1,884,160 bytes. Avoiding successful-path range-result allocations and giving `apply` a direct singleton path brought that run under budget. Later public-barrel and coordinate-index changes caused one rerun to exceed RSS by 1,069,056 bytes; preserving split-leaf priorities and avoiding an unnecessary recursive remerge reduced allocation. The current 100,000-edit rerun passed all three resource budgets; `.artifacts/document/T009-results.json` contains its metrics.

The deterministic edit suite covers empty documents, a giant line, UTF-16 surrogate boundaries, stale versions, atomic overlap rejection, old snapshot retention, storage-only compaction and tree invariants. The T009 suite and fragmentation budget were rerun after T011 made rope storage runtime-private and froze persistent nodes/chunks. No failing required T009 gate remains.

## Limitations and next action

T009's listed acceptance items pass. The resource budget was qualified on the pinned Linux ARM64 environment only; it does not establish release-wide process memory or full editing latency. T010 and T074 are now recorded separately in the plan and their evidence reports.
