## Observable result

The Xi performance rule now performs bounded local data-flow checks for inferred
string variables, including common string-producing initializers and visible
string aliases. It reports loop-carried `+=` and `s = s + part` assignments in
H0/H1. It also tracks the identity of locally declared arrays through nested
loops and reports joins that repeatedly rebuild a string from an array grown by
`push`, `unshift`, or `splice`. A per-iteration scratch array and a single
return-path join are accepted as bounded outcomes. Variable identity prevents an
unrelated array or shadowed numeric variable from causing a finding.

The documentation states the analysis boundary: helper/member/dynamic calls,
native or hidden allocations, general type inference, arbitrary IO wrappers and
whole-program aliases still require owner review, work counters and measurements.

## Failure cases and recovery

The first production run found two false positives: a single join on an early
return path in `packages/vim/ex/index.ts`, and a per-row scratch array in
`packages/vim/ranges/normalize.ts`. The rule was tightened to recognize those
bounded lifetimes; both were rerun through `bun run check` and no production
findings remained. No suppression or execution-class downgrade was added.

No new production performance debt was surfaced after the correction. Existing
owner remediation obligations from T119 remain tracked by T109/T111/T112/T116;
this infrastructure result does not waive their runtime acceptance.
