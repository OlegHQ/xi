## Observable result

The disposable spike normalizes OpenTUI key press/repeat/release, paste bytes, low-level parser responses, renderer focus/blur callbacks, and hit-tested mouse callbacks into a single discriminated event vocabulary in `spikes/input/types.ts`. It retains raw/protocol identity, promotes OpenTUI's `repeated:true` event to canonical `eventType:"repeat"`, preserves paste bytes as hex, and keeps mouse positions zero-based. Parser CSI focus responses remain responses; only the renderer adapter produces focus/blur, matching OpenTUI's public layering.

The real CLI PTY path uses `exitOnCtrlC:false`. In both legacy and Kitty input modes, Ctrl-C was delivered and the process remained alive until the later `q` event. The pinned oracle fixture `INP-ORACLE-CTRLC-01` returned `aXbc`, cursor byte column 2 on line 1, Normal mode, no blocking state/error, and a modified buffer.

OpenTUI 0.5.11's default 20 ms parser timeout can split a valid UTF-8 code point into legacy key events if its bytes arrive after that deadline. The spike records this as `INP-UTF8-CHUNK-LATE-01` and supplies a disposable UTF-8 boundary adapter; the guarded CLI PTY retained one `é` across a 25 ms gap. The unguarded baseline was also run and recorded. Product code remains unimplemented; T035 now owns porting and qualifying the adapter.

## Failure cases and recovery

- `INP-ESC-ALT-01`: Escape is emitted at the measured parser threshold; a later `ESC x` remains a separate Alt-x key event.
- `INP-TAB-CTRLI-LEGACY-01`: both legacy `09` inputs decode as Tab, demonstrating the byte collision. `INP-TAB-CTRLI-KITTY-01` distinguishes Tab from Ctrl-I.
- `INP-UTF8-CHUNK-01`: `C3` and `A9` in separate parser pushes with 5 ms manual time between them emit one `é`. `INP-UTF8-CHUNK-LATE-01` documents the 20 ms fallback instead of hiding it. The unguarded PTY run reproduces the fallback after 25 ms; the guarded path preserves one character.
- `INP-PASTE-ESCAPES-01`: escape-looking bytes, newline, and `q` remain in one paste payload. The PTY emitted one paste event and no command events from its contents.
- `INP-CTRLC-LEGACY-01`, `INP-CTRLC-KITTY-01`, and `INP-ORACLE-CTRLC-01`: Ctrl-C remains an editor input and matches the pinned oracle's insert-to-Normal result; PTY process survived until `q`.
- `INP-KITTY-REPEAT-01` and `INP-KITTY-RELEASE-01`: repeat and release remain distinct canonical events. `keyrelease` was delivered once; repeat retained `repeated:true` and normalized to `eventType:"repeat"`.
- `INP-FOCUS-01`: parser responses stay distinct from public renderer events. PTY repeated focus-in/out reports caused no duplicate public callback.
- `INP-MOUSE-SGR-01`: SGR left-down at terminal cell `(6,3)` normalized to zero-based `(5,2)` once through parser and once through the renderer path.
- All three real PTY modes restored the original raw-mode state and disposed renderer resources on normal `q` shutdown.

## Limitations and next action

The measured capability matrix covers pinned OpenTUI 0.5.11 on Linux ARM64 with exact bytes injected through a kernel PTY. It does not qualify xterm, Kitty, WezTerm, tmux, SSH, suspend/resume, or other host terminals. The fixed parser timeout has a visible long tail in the PTY event trace, and the unguarded parser can reinterpret a late UTF-8 continuation as keys. These are recorded facts, not release passes.

T006's feasibility and reporting acceptance is complete. The UTF-8 guard is spike-only; T035 has a new explicit dependency on T006 and must implement the UI-owned adapter and pass the delayed-continuation requirement through production routing. T013 also depends on T006's canonical event contract. No product editor runtime was added by this ticket.
