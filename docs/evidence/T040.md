## Observable result

`ExplorerTree` lazily enumerates expanded directories, filters hidden and
ignored entries by policy, sorts directories before files, preserves stable
node identities through external insertion and rename, and keeps explicit
permission, empty, symlink-cycle and overflow states. `ExplorerNavigationController`
owns panel movement, disclosure, opening, first/last navigation and filter
policy. The UI surface consumes only the immutable read port.

The production launcher adapts `NodeFilesystemPort` into the Explorer port,
starts root enumeration and watching asynchronously, opens the panel with
`Space v f`, supports navigation and `/` filtering, auto-reveals the active
workspace file, opens selected files through the normal document/workbench
path, and restores editor focus on close. External root insertion and rename
are reconciled through watcher invalidation; `(device,inode)` identity keeps
the selected node stable.

## Performance and failure evidence

Directory reads, metadata reads and watcher callbacks are asynchronous and
bounded to the expanded directory; no whole-workspace scan occurs on a tree
key path. The production PTY confirms external reconciliation without
blocking editor input. The isolated OpenTUI fixture captures populated and
state rows at bounded dimensions.

The first aggregate run and several immediate-repeat attempts exposed a PTY
fixture timing race: it issued the rename as soon as the insertion refresh
published `ready`. The fixture now waits 100 ms for that watcher callback to
unwind before the separate rename. It passed 8/8 standalone repeats and the
24-fixture aggregate rerun. No production watcher behavior was changed; this
does not claim arbitrary bursts of external filesystem mutations are covered.

- `T040-SYMLINK-01` through `T040-SYMLINK-03`: symlink and traversal-disabled
  states remain visible and cannot enter a cycle.
- `T040-EMPTY-01` through `T040-EMPTY-03`: empty directories remain visible
  with an explicit empty state.
- `T040-PERMISSION-01`: unreadable directories publish a visible permission
  error instead of disappearing.
- `T040-OVERFLOW-01/02`: overflow marks and refreshes the affected expanded
  directory while preserving the watcher lifecycle.
- `T040-E03-06` through `T040-E03-10`: insertion and rename preserve selected
  node identity and update its path/name independently of row indexes.

## Limitations

The native watcher reports invalidation and the service rereads the affected
directory; it does not infer an OS rename event from the watcher callback.
Metadata and Git decoration remain optional injected ports, as required by
the service contract. T041 owns editable directory operations.
