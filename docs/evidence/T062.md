## Performance and visual evidence

These are resolver/model measurements with local sample counts. The new PTY probe measures parent write to a production frame marker and expected text prefix; it excludes physical display scanout. The latest run is within the proposed p95/p99 limits, while an earlier run on the same shared runner exceeded p95, so this is not a stable performance gate. The measurements do not include loaded LSP/search/Git, startup, CPU/GC/native RSS attribution for the full application, subprocess cost, 1 GiB search, 100 MiB file, or Neovim comparison measurements. No dedicated stable performance runner is available in this worktree.

## Failure cases and recovery

The original wrapped-left over-budget path was reproduced and fixed with an immutable-snapshot line-edge fast path; T016 functional and oracle tests were rerun. T089 scale data retains p50/p95/p99/max values for review. The 10,000-sample input-output probe retains both the latest within-target run and the earlier over-target shared-runner result; it does not silently relax the threshold.

## Limitations and next action

T061 and T089 are prerequisites and remain unproven. The mandatory full reference-host budget matrix, trace attribution, native comparison, loaded-system workload and retention proof is incomplete; repeated stable-runner confirmation is also missing because the local p95 varied across the target boundary. Keep T062 unproven until those measurements run on a recorded stable runner.
