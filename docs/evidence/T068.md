## Observable result

`PullDiagnosticStore` owns one server's document/workspace result IDs and immutable snapshots. It clears items while a pull is loading, accepts unchanged reports only with the exact current baseline, applies workspace responses atomically, and rejects late, cancelled, malformed or partial results. `LanguageServerSession` sends the LSP document/workspace requests, checks document versions before publication, responds to `workspace/diagnostic/refresh`, and publishes through the existing per-server `DiagnosticStore` key so push and pull results cannot duplicate each other. Restart and close invalidate pull state and shared diagnostics.

## Performance and visual evidence

The store caps each report at 10,000 items, keeps one snapshot per URI, and does no document text scan. Pull refresh is asynchronous and does not block ordinary document input. No dedicated visual surface is introduced; the existing Problems read owner receives one per-server source. Separate editor latency and memory qualification remain in the performance tickets.

## Failure cases and recovery

Refreshes carry per-URI generation barriers and a server-wide restart epoch. A restarted server invalidates old result IDs and items. Provider unavailable, failed, stale and cancelled outcomes remain explicit states; malformed or partial workspace responses invalidate all affected URIs together. Closing a document removes its pull snapshot and shared diagnostics.

## Limitations and next action

The store is wired to `LanguageServerSession` and the framed transport. Cross-server diagnostic presentation policy and Problems interaction remain owned by T049; no pull-specific visual surface is required by this ticket.
