## Observable result

`executeVimMultiMacro` wraps the existing bounded macro executor with one immutable selection-set context per dispatched token. A callback is invoked once for the logical command and returns both its atomic effect and the next selection set; it is never replayed once per cursor. Existing recursion, repeat-count, work-budget and cancellation guards remain active, while failed current commands stop playback after previously committed commands and do not publish partial selection state.

## Performance and visual evidence

No render budget applies to macro state planning. Execution retains bounded token/depth/repeat/work limits and yields progress through the existing slice callback; terminal/UI qualification remains downstream.

## Failure cases and recovery

Recursive calls, missing registers, depth/repeat/work limits, cancellation and dispatch failures return typed execution status. A failed command stops playback after prior committed commands; the current command's selection state is not installed. Macro playback receives scalar parser tokens and never interprets register-vector metadata as executable macro text.

## Limitations and next action

T092 does not claim command-dispatch wiring or a launchable editor. G2 qualification T033 must combine this one-stream executor with the register, repeat, history and UI preview fixtures. The executable editor startup and full UI gates remain covered by downstream tickets.
