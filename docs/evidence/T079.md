## Observable result

`VimRegisterBank` now retains an immutable vector beside the primary native scalar for multi-member yanks and deletes. Vector writes validate nonempty arity, primary index, homogeneous register type and block width before changing state. Multi-delete rotates vector metadata once, uppercase named writes append corresponding fragments only when arity and type match, black-hole writes remain no-ops, and singleton writes clear vector metadata while preserving native scalar behavior.

`prepareVimMultiPut` validates one source snapshot and equal fragment/member arity, prepares each typed put against its own cursor, normalizes all edits atomically and returns no partial plan on stale or conflicting input. Vector clipboard export joins canonical fragments through the existing clipboard port; import writes a text-only scalar vector and propagates provider denial without touching the prior bank.

## Performance and visual evidence

No render or latency budget applies to immutable register planning. Vector validation and multi-put preparation are synchronous pure plans over supplied fragments and snapshots; clipboard I/O remains asynchronous through the injected port. UI and scale qualification remain downstream tickets.

## Failure cases and recovery

Empty vectors, invalid primary indexes, mixed types, invalid block widths and arity mismatch reject before bank or document mutation. Black-hole writes return the same bank. Stale member snapshots and edit conflicts return typed multi-put failures. Clipboard provider denial is returned separately from any document plan.

## Limitations and next action

T079 does not claim final register integration into command dispatch or a launchable UI. T080 consumes the vector-compatible register/repeat boundary, and T033/T034 provide qualification and the first editor shell.
