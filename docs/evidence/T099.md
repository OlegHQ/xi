## Observable result

The headless harness scans key input by ASCII notation delimiters. It passes only recognized tokens such as `<Esc>` and `<F5>` through `nvim_replace_termcodes`, preserving other UTF-8 bytes as literal input. An unknown angle sequence emits its first `<` literally and resumes scanning, so `<<Esc>` preserves `<` and still expands Escape. Recognized names cover the repository's oracle key notation, including modifier, function, keypad, mouse, and Undo names.

PTY readiness now strips ANSI CSI and OSC controls, retains line boundaries, and decodes accumulated output as strict UTF-8; incomplete scalars cannot match. It matches all marker scalars in order while tolerating terminal cell padding between them. The default marker is the complete first fixture line. The PTY reader answers the xterm queries emitted by the pinned Neovim, including DSR, CPR, device attributes, mode, keyboard, and background-color queries. Error cleanup dismisses a possible hit-enter prompt and sends a normal quit; `terminalRestored` is true only when the transcript contains both alternate-screen exit and cursor-show sequences.

## Failure cases and recovery

- The raw `f😀` and `i😀<Esc>` sequences pass through the production headless helper without termcode conversion of literal UTF-8. The pre/post `f😀` snapshots verify unchanged document text and registers, while the cursor reaches the expected byte column.
- `T099-PTY-MARKER-TIMEOUT-RESTORE-01` forces a one-second marker timeout after startup and confirms `ESC[?1049l` plus `ESC[?25h` in the retained transcript.
- `T099-PTY-ORACLE-FAILURE-RESTORE-01` exits Neovim with `:cq` and confirms the same terminal restore markers.
- PTY output from the pinned oracle previously showed `E1568: Terminal did not respond to DSR`; the new query responder removes that startup error and allows the full marker to be captured.

## Limitations and next action

The PTY query responder covers the xterm query forms observed from pinned Neovim 0.12.4; it is not a general terminal emulator. No T099 acceptance item remains unmet. The ticket ledger remains under the root agent's control.
