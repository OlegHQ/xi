## Observable result

Document history now accounts for copied UTF-16 payload, estimated private
metadata, persistent source roots and step count. Adjacent single-character
insertions in one group coalesce into bounded 8 KiB text runs, avoiding one
history step and repeated whole-prefix concatenation per key. Large inverse
payloads retain an immutable source snapshot and aligned EOL metadata; the
whole-document delete/undo path restores the retained rope root directly and
does not flatten the deleted text.

Selection-only history now charges cloned serialized states by estimated bytes,
enforces a four MiB cap in addition to its entry cap, and evicts oldest states
with explicit accounting. Register storage remains immutable and replacement
releases the old bank through normal ownership; complete register-vector and
large-register workload accounting remains outstanding.

## Performance and visual evidence

The PF06 probe used a 104,857,600 UTF-16-unit (`x\n` repeated) production
document and 52,428,800 LF breaks. After deletion, history reported
`retainedUtf16=0`, `retainedPrivateBytes=352`, `retainedRootUtf16=104857600`,
`retainedRootSnapshots=1`, and `stepCount=1`. Undo restored the exact source
string and EOL metadata; root restore reduced the measured undo wall time from
the earlier 1,524.157 ms flattening path to 0.255 ms.

This is one diagnostic process on a shared host. It is not a 30-trial p95,
allocator census, register-vector matrix, 100k branch/edit matrix, two-view
selection release test, or reference-host qualification. Visual evidence is not
applicable to this document/history slice.

## Failure cases and recovery

Existing tests continue to reject malformed history, stale/overlapping edits,
invalid selection values and failed selection mappings without partial
publication. A retained source root is only used when the inverse is a single
whole-document replacement; other source-backed inverses use bounded replay
materialization. Old snapshots and redo branches remain live until their owner
is evicted.

## Limitations and next action

- `HISTORY`, `HISTORY-LARGE`, `ENGINE-EDIT-ALLOC` and `SELECTION-MAP` still lack
  their required sample counts, runtime allocation/GC data, full branch/edit
  matrices and qualified reference-host evidence.
- Register and repeat payloads are still represented by their existing immutable
  value contracts; shared large register payloads and replacement release need
  production counters and a dedicated workload.
- General large middle deletes, multiple source-backed edits and persisted
  lazy-source history need additional replay/serialization coverage.
- T106 currently has zero observed production obligations, so this report cannot
  certify T110 or unblock T115/T062.

Next action: wire T110's production producers into the T106/T115 matrix and run
the required PF05/PF06 history, selection-cardinality and allocation trials on a
qualified reference host.
