## Observable result

`WorkbenchHistoryCoordinator` associates each native document undo entry with the immutable before/after selection sets and originating view. Undo/redo requests the document operation once, restores the active origin only when that view is still live, and maps all other live views through the committed change map. Closing the origin never recreates it. Selection-only transitions use bounded per-view `VimSelectionHistory`; they branch after undo, map through intervening service edits, and do not change document text, revision, dirty state, native undo entries, events or registers.

## Performance and visual evidence

No separate performance threshold or visual output is assigned to this history coordinator. Selection history is bounded by the existing `VIM_SELECTION_HISTORY_LIMIT`; document mapping uses the supplied immutable change map and does not scan unrelated text. No renderer was changed.

## Failure cases and recovery

The acceptance fixture covers undo after a new edit with two redo branches, invocation from a non-origin view, origin disposal before undo, selection history branching, unmappable history diagnostics, and a service edit between selection transitions. A failed mapping leaves the live state unchanged and reports a typed `history-mapping-failed`/`unmappable-history` result. Selection-only undo/redo never emits a document change or mutates registers.
