## Observable result

`RipgrepSearchBackend` invokes ripgrep through `ProcessPort` using argv and
machine-readable JSON. The parser accepts split/coalesced UTF-8 chunks,
converts ripgrep's byte ranges to zero-based UTF-16 columns, normalizes valid
paths to the workspace root, retains `base64:` paths for invalid-byte names,
and terminates on a bounded output flood. It emits the first match and later
bounded batches while the service retains a final generation-checked result.

`RealtimeSearchService` debounces at 40 ms, cancels obsolete requests,
resolves cancelled debounce promises, rejects late process output, preserves
stale prior results for invalid regular expressions, and merges current dirty
buffer snapshots without disk duplicates. The launcher exposes `Space /` and
`Space v s`, query input, literal/regex, case, whole-word and hidden-file
toggles, grouped result rows, bounded selection navigation and Enter-to-open.
The search overlay returns to its prior query context after dismissal.

## Performance and resource evidence

The benchmark uses 240 files, one matching file per query, 30 warm samples,
real Bun subprocesses and the production 40 ms debounce. It reports parent
CPU p50 1.73 ms, p95 4.09 ms and RSS 73,887,744 bytes at completion. Search
output is parsed in bounded batches; dirty-buffer snapshots are captured
after debounce rather than inside the keypress handler. The benchmark is
affined to one CPU for reproducibility; the unpinned shared-run measurement
showed scheduler noise and is retained as diagnostic context, not as a pass.

The first-result target is 100 ms p95 and cancellation target is 50 ms p95
for this T043 workload. Full PF08/PF09 100k-file/1 GiB throughput, aggregate
loaded-system CPU, and ten-buffer RSS qualification remain owned by T112,
T115 and T106; this ticket does not claim those release gates.

## Failure cases and recovery

- `T043-RG-ENCODED-01`: ripgrep's `path.bytes` representation is preserved as
  a `base64:` display path instead of corrupting the filename or assuming
  UTF-8.
- `T043-RG-FLOOD-01`: parser output above 8 MiB by default and 4 KiB in the
  focused fixture terminates the child and returns a typed backend error.
- `T043-PROCESS-EXIT-01`: replacing a query cancels the old process, resolves
  the old request as stale and prevents its late match from replacing the new
  generation.
- `T043-REGEX-01`: invalid regex input reports an inline error and keeps the
  last valid matches in stale state.
- `T043-DIRTY-01`: the current dirty buffer replaces same-path disk matches
  and carries its document version.
