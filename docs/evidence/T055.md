## Observable result

`FormatterPipeline` runs ordered formatter stages over an immutable document snapshot and checks the document version before and after each stage. LSP providers return validated UTF-16 range edits; external formatters run through the typed process port with argv substitution, bounded output, cancellation and timeout handling. Stable formatting performs two passes before application.

Save formatting is integrated into the production launcher behind the explicit `XI_FORMAT_ON_SAVE=1` and `XI_FORMATTER_COMMAND` configuration used by the composition root. Ctrl-S starts the save request without waiting on formatter or disk latency, so subsequent Vim input remains admissible. A formatted result is applied through the workbench coordinator with origin `formatter`, one undo group and mapped document anchors. If the document changes during formatting, the pipeline retries against the newer version; stale output is never written. Failed formatting leaves the disk file unchanged and reports a typed error.

## Performance and visual evidence

Formatting is off the ordinary keystroke path. Ctrl-S no longer holds the input queue while a formatter or persistence operation awaits. The existing renderer queue coalescing and cached repaint work remains covered by the T034 visual fixture and launchable PTY journeys. No numeric formatter latency or memory qualification is claimed; the full PF/spec-15 performance matrix remains owned by T106/T115 and is currently unproven.

## Failure cases and recovery

- A document version change during either formatter pass returns `stale`; the launcher retries against the current snapshot up to four bounded attempts.
- Invalid or overlapping UTF-16 edits, invalid replacement surrogates, nonzero process exits, invalid UTF-8 output, output over the configured bound, cancellation and timeout return typed formatter failures before document application.
- A second formatter failure aborts the chain. The production PTY confirms the existing disk file remains unchanged.
- A successful format is one `formatter` undo transaction and maps active and secondary selection anchors through the committed change map.

## Limitations and next action

The current production composition exposes external formatter selection through explicit environment configuration; loading user `languages.toml` formatter settings and a live LSP `textDocument/formatting` request remain future composition work. The ticket's formatter provider, range, ordered-chain, stale-save and failure acceptance is complete. Full performance certification remains unproven under T106/T115 as required by the plan.
