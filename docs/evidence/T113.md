## Observable result

The filesystem contract now has optional ordered chunk readers and bounded
atomic chunk writers. `NodeFilesystemPort` reads with a 64 KiB stream and
writes each encoded snapshot through a temporary file, sync, atomic rename and
directory sync. Persistence selects those methods when available and retains
the existing whole-byte adapter path for older ports.

The document owner now decodes UTF-8 incrementally, handles a UTF-8 BOM and
UTF-8/EOL boundaries split between chunks, builds packed line-ending metadata,
and appends normalized text directly into the initial rope. Snapshot encoding
uses bounded UTF-16 windows. Invalid UTF-8, NUL input and ambiguous automatic
line-ending input remain lossless read-only documents.

## Failure cases and recovery

The focused fixture splits a UTF-8 scalar and CRLF across arbitrary chunks and
checks exact normalized text, EOL metadata, BOM and re-encoding. A cancelling
writer cancels after the first encoded chunk; the atomic writer removes its
temporary path, leaves the previous target bytes intact and the document stays
dirty. Existing T037 fault injection continues to cover write and recovery
failures.

## Limitations and next action

- `openFile` and `#readIdentity` now use chunked input through the production
  Node adapter, but checkpoints and journal compaction still serialize the
  complete recovery JSON synchronously in the persistence service.
- The chunk reader retains bounded input chunks until validity is known so a
  rejected file can remain lossless; invalid-input peak accounting is absent.
- PF11 delayed/failing storage, dirty-age reporting, formatter patch streams,
  30-trial distributions, reference host qualification and complete allocation
  provenance remain unmeasured.
- The source hash table requires correction of the persistence row before any
  later evidence regeneration; this report does not claim a release pass.
