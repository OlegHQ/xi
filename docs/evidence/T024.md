## Observable result

`packages/vim/repeat/index.ts` stores a frozen semantic target instead of old coordinates or raw screen keys. Targets retain operator motion/count, insert entry/mode/text/literal-control intent, visual selection metadata, or put register/type/count. `replayVimDot` passes the target, current versioned snapshot, current cursor and effective count to an owner resolver, so motions and register payloads are reevaluated at replay time. A count preceding dot replaces the recorded count while leaving repeat state unchanged until the replay commits. Failed commands, yank/service actions, undo and interrupted inserts preserve the last successful target.

Selection metadata is cloned and recursively frozen at the repeat boundary. Insert text rejects malformed UTF-16 and requires explicit `literal-control` intent for carriage returns. Invalid target/count/cursor inputs return typed failures before a resolver runs. The package does not mutate documents, registers or selections; its public constructors and replay entrypoint are exported through `packages/vim/src/index.ts` for coordinator dispatch.

## Performance and visual evidence

No rendering or performance threshold applies to this pure semantic state/resolve module. Resolution is bounded to target cloning, validation and one resolver callback; document scans and edits remain in their owning packages.

## Failure cases and recovery

`T024-ORACLE-FAILED-01` pins `dw`, a failed `dfZ`, and dot replay in Neovim; the failed command leaves the prior delete target and dot removes the next word. The test also covers dot at an EOF resolver failure, an interrupted insert preserving the put target, malformed literal-control input, absent dot target, invalid cursor/count and a register payload changed between two replays. Undo and external service events preserve the target by identity.

## Limitations and next action

The workbench/parser dispatcher must wire successful native command outcomes to `applyVimRepeatEvent` and invoke `replayVimDot`; multi-cursor repeat-vector policy remains downstream owner work. No T024 acceptance item in the repeat contract is unmet.
