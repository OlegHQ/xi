## Observable result

`IncrementalSyntaxHighlighter` now runs its owned line scanner as a resumable
generator. The production scheduler runs one bounded slice per timer turn, so a
large parse can yield before completion and a newer input sequence can cancel
stale active work. The parser keeps an immutable text read replica and publishes
only a result whose request sequence is still current.

Queued and active request text now consume an explicit UTF-16 credit in addition
to the request-count cap. Old queued requests are evicted before newer work;
payloads that cannot fit are rejected without changing the current generation.
Missing or non-contiguous deltas trigger a full bounded resync and are counted.
Disposal clears queued and active work and settles flush waiters. No canonical
document buffer is transferred or mutated.

## Failure cases and recovery

The focused test drives a large parse one scheduler task at a time, submits a
new request during an active slice, and verifies the old result is ignored. It
also rejects a request over the configured UTF-16 credit, performs one explicit
full resync when a delta is missing, and disposes a parser with scheduled work
still pending. Flush returns after queue and active work are released.

The existing syntax fallback fixtures continue to report malformed UTF-16,
giant-line and large-file conditions as typed results. No failure was found in
the exercised functional cases.

## Limitations and next action

T112 remains unfinished until PF09 production adapters measure the full service
flood, worker/replica/native costs, input-to-state latency, cancellation and
loaded E14 behavior with required independent samples. A timer turn is now only
the boundary between parser slices; the diagnostic run is not evidence that all
slice or aggregate budgets pass. T115 must wire and qualify those production
cells before this ticket can become `done`.
