## Observable result

`packages/contracts` now exposes inert, versioned contribution contracts for immutable read ports, edit proposals, provider origins, cancellation and scoped feature modules. `packages/workbench/contributions` stages commands, picker/panel models and providers, validates the complete candidate, then publishes one immutable generation. Provider selection is deterministic by priority and ID; equal-priority capability conflicts are rejected. Each module receives a disposable resource scope, and disposal cancels active provider requests and removes all registered contributions. The checked-in `createExampleContributionModule` uses the same public ports as future built-in consumers.

The edit path only receives `ContributionEditPort.propose`; a contribution never receives a document owner, writable text store, UI node or composition root. Provider results carry module/provider/capability origin. Failed module activation and duplicate command/provider/model registration leave the exact last-good snapshot and handlers usable.

## Failure cases and recovery

- A duplicate module, command, provider, model or equal-priority provider capability is rejected before publication; the test compares the snapshot object and dispatches the prior command after each rejection.
- A provider disposed while awaiting work receives cancellation; its late result is suppressed and the provider is absent from inspection.
- A provider can request only a typed edit proposal through the public edit port. The fixture records that proposal and confirms the provider origin; no direct document mutation path is available.
- Module and registration handles are scope-owned and idempotent. Module disposal cancels requests, unregisters command handles and removes provider/model records.
- Import ownership is enforced by the public DAG and undeclared/deep-import sentinels in the architecture check.
