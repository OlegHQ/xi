## Observable result

`spikes/ui-react/build-cli.ts` compiles the actual application three ways without
editing production files: captured private-scheduler terminal adapter, current public
Core scheduler, and that public scheduler with a React-owned status-message surface.
All variants resolve Core from the same root installation. The baseline terminal source
is `.artifacts/ui-declarative/baseline/terminal.ts`; other source is shared with candidates.

`launch.tsx` replaces the actual status surface, not a duplicate overlay above it. React
subscribes to the real status controller and command visibility. The actual document,
Vim engine, input router, services, viewport and other panels remain production code.
The empty initial React commit precedes legacy attachment to avoid root clearing.
This temporary coexistence is not the proposed production ownership model.

24/24 bounded journeys passed (4 independent processes × 3 variants × idle/task load).
Each checks first movement, five paced motions, six Unicode insertions, visible error
status from `:task missing`, command-line takeover, final file bytes and clean exit.
Task runs use a configured Python child emitting ~2 KiB every 3 ms. Output panel closes
before measurement; heartbeat advances during editing and the task has not exited.
Two earlier corrected surface smoke runs also passed. This proves a real React surface
can coexist with the existing editor; it does not establish complete panel parity.

These exceed budgets in multiple conditions, and **do not isolate application latency**.
The Python VT parser and observer run on the reader thread; the input producer is a
separate thread sharing its GIL. Significant injection slippage is retained. For example,
Core idle scheduled-to-correct p95 is 49.73 ms vs write-to-correct 17.49 ms. Neither number
can establish native-level speed. Bounded loaded runs appearing faster is not evidence
that load improves performance. No statistically supported nonregression claim is made.
A producer process independent of the parser and a calibrated observation boundary are
needed before interpreting tails. Absolute thresholds are unchanged.

Raw ANSI and parsed screens are retained. No new graphical terminal screenshots were
visually reviewed for this compiled variant; visual acceptance remains open. The earlier
isolated T134 screenshots do not certify this replacement surface or full production UI.
CPU, allocation rates, GC, native/worker retained memory, large-file/startup classes,
full background-service matrix, paired Neovim and physical latency are unmeasured.

## Failure cases and recovery

- Initial observer incorrectly expected hardware cursor coordinates. Xi intentionally
  hides that cursor and paints it into cells. Corrected to inspect actual cursor cells.
- Initial wide-cell reconstruction double-counted explicit continuation spaces emitted
  by Core. The saved screen showed correct `aé漢aé漢`; the observer rejected it. Corrected
  reconstruction with a runnable wide-cell regression; failures retained in `surface/`.
- The full motion failure persists independently in all variants. Recorded private/React
  event lists show all 80 writes and no feeder error, with 50 completed observations.
  This does not distinguish dropped input, stale painting, or a remaining observer flaw.
  Do not attribute it to React or declare a product fix without minimizing it.
- Failure artifacts are saved before fixture cleanup; test processes are killed on
  failure. Existing project files and personal config are not used as fixtures.
- The prior T116 loaded diagnostic also has a focus/completion-boundary problem: an
  Escape from search can leave panel navigation active, and previously accumulated CSI
  bytes can satisfy an output check. Those prior numbers are not qualification evidence.
  The new producer explicitly closes task Output and checks editor cursor/text state.

## Limitations and next action

T135 remains unfinished because full-path correctness/qualification is unresolved.
T136 makes the measurement/burst blocker explicit; T137–T139 describe the independently
reviewable shell, panel and overlay retirement, with production adoption behind T133
and measurement qualification. No production React dependency or full replacement has
been shipped. The plan preserves the custom optimized viewport and semantic input
serialization while removing imperative UI composition rather than wrapping all of it.

## Follow-up

T136 resolved the 50-of-80 result: lowercase Core arrow names were not canonicalized
by the Vim adapter. Burst j input worked; the 30 Down events were ignored. It also
replaced threaded live parsing with independent injection and timestamped output
validation. The measurements above remain historical; see [T136](T136.md) for corrected
results. This does not retroactively pass T135 or production migration gates.
