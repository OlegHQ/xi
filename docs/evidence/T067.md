## Observable result

`LanguagePresentationFeatures` stores immutable, versioned folds, selection-range trees, inlay hints and code lenses per document. It accepts nested folds, rejects invalid and crossing ranges, validates selection-range containment and depth, bounds viewport decoration reads, and rejects stale generations/versions before publication. Lazy hint/lens resolution is tokenized so an older response cannot replace a newer one; explicit lens execution uses the currently resolved command and does not touch selections.

## Performance and visual evidence

Feature publication is bounded by protocol list size and does not scan document text or invoke UI code. `visibleHints` clips results to a logical-line window and hard limit. Layout consumes immutable fold/annotation data through its existing bounded projection path. No new performance qualification is claimed here; the repository-wide latency and memory budgets remain the separate T106/T111/T112/T115/T116 gates.

## Failure cases and recovery

Invalid/malformed/crossing folds and invalid selection trees return typed failures without publishing partial lists. A fold containing the active cursor is relocated to its immutable header projection by layout, while Vim's logical screen-motion state remains document-owned and is validated by T031's folded oracle fixture. Older hint/lens responses cannot move selections or execute an obsolete command. Resolver/executor exceptions are returned as typed failures, and disposal clears all cached presentation data.

## Limitations and next action

The ticket covers the versioned language owner and its existing layout/UI read path. Cross-feature multi-cursor composition remains T088's explicit qualification, as required by the plan.
