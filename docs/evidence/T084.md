## Observable result

The prototype uses the pinned OpenTUI `StdinParser` and renderer as the only protocol decoder. A Linux kernel PTY drove the actual renderer at 300 columns. SGR press, drag, release, wheel-up/down and modifier reports reached the renderer at the expected zero-based cells; seven partial SGR packets, split at different byte offsets, each produced one canonical pointer event. The PTY probe’s additional stdin listener records chunk hex only for test instrumentation and performs no parsing or dispatch.

OpenTUI 0.5.11 sends one captured left-release through renderer callbacks `drag-end`, `up`, `drop`, and a second `up`. The spike adapter in `prototypes/pointer/renderer-pointer-adapter.ts` coalesces that pinned callback sequence into one canonical release while using only the renderer callback path. The enabled PTY trace contained 31 raw renderer callbacks and 28 normalized in-frame mouse reports; an out-of-frame report was rejected before reaching a renderable. Adjacent keyboard and bracketed-paste content remained separate: only `x`, `s`, and `q` were key events, while `x ESC [ A LF q` remained one paste payload.

The Xi baseline setting `enableMouseMovement:false` enabled button/motion mode 1002 and SGR mode 1006 without all-motion mode 1003. The comparison run with `enableMouseMovement:true` added 1003. The PTY observed SGR mode enable/reset, raw-mode restoration on quit and SIGTERM, renderer suspend/resume, and a SIGTSTP wrapper that suspends before stopping and resumes on SIGCONT. With `useMouse:false`, an injected mouse report produced neither a mouse event nor a key event.

The public parser also reproduces two integration defects for downstream ownership: unbounded SGR decimal coordinates and incorrect `rawHex` for X10 bytes. The former is assigned to T085’s versioned hit-test boundary. The T035 canonical-input contract and fixture path were updated for exact X10 byte preservation; production remains unimplemented.

## Failure cases and recovery

- Lost release: the PTY sent left-down, suspended without an up report, resumed, then sent motion and up. The canonical sequence was down, move, up; no stuck drag remained. Fixture MP02-LOST-RELEASE-01.
- Captured release duplication: pinned OpenTUI emitted the four callbacks listed above from one wire report. The spike adapter coalesced them to one logical up; PTY assertions fail if this callback sequence changes. Fixture MP01-SGR-RELEASE-01.
- Oversized SGR coordinate: `ESC[<0;999999999999999999999999999999999999;1M` parsed to `x=9.999999999999999e+35`; OpenTUI does not bound the value. T085 must reject or clip against the current frame before hit testing. Fixture MP02-COORDINATE-OVERFLOW-01.
- X10 limits: coordinates top out at zero-based 222 and motion is reported as `move`, without pressed-button drag state. Use SGR 1006 for wide terminals and drag. Fixtures MP01-X10-LIMIT-01 and MP01-X10-MOTION-01.
- X10 raw trace: wire bytes `1b5b4d20ffff` become canonical `rawHex=1b5b4d20c3bfc3bf` because the T006 prototype UTF-8-encodes Latin-1 carrier characters. T035 now owns the exact-byte acceptance item. Fixture MP01-X10-RAW-HEX-01.
- Shift/Alt/Ctrl bits survived injected SGR parsing. Whether a terminal consumes Shift before Xi sees a report was not testable without a named interactive terminal.
- Named matrix: Linux PTY protocol injection is tested, not a terminal emulator. tmux 3.6a and GNU Screen 4.09.01 were available but not independently qualified. OpenSSH client 9.6p1 was present without a controlled remote endpoint. WezTerm, Kitty, xterm and foot executables were unavailable. No claim is made for physical mouse forwarding through these terminals or SSH.
- OpenTUI does not supply Xi’s job-control signal policy automatically. The PTY tested an explicit wrapper around `CliRenderer.suspend()`/`resume()`; Xi must implement that policy in its platform/UI adapter.
