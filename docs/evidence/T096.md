## Observable result

Xi parses regular Vim patterns into a source-spanned AST and evaluates the regular subset using an ordered Thompson NFA. The pinned Neovim binary is used only by development oracle fixtures. Regular patterns do not use JavaScript `RegExp`; patterns requiring backreferences or lookaround use the separately budgeted AST evaluator and do not silently fall back to another regex dialect.

The scoped dialect covers magic modes and switches, pattern-local case controls, regular groups/alternation, quantifiers, built-in and POSIX classes, newline-inclusive atoms/classes, line and word anchors, captures 1–9, `\zs`/`\ze` reported spans, and zero-width advancement. Invalid, unsupported and resource-limited inputs retain typed errors with source spans where a pattern source is available. Output-limit errors now also carry the root pattern span.

## Performance and visual evidence

Visual evidence is not applicable to this pure evaluator ticket. The in-process benchmark used 5 warmups and 50 samples on Linux arm64 with Bun 1.3.13; it has no target-latency threshold and does not include editor input or terminal paint.

The 1,001-UTF-16-unit regular workload (`\\v(a|ab)+z`) completed at 19,013 deterministic work units. The latest retained 50-sample run measured p50 2,804.288 µs, p95 4,055.620 µs, p99/max 6,408.616 µs. Resuming in 128-work-unit slices took 149 slices (p50 2,669.121 µs, p95 3,862.203 µs, p99/max 4,564.410 µs). The nonregular backreference workload hit its explicit 50,000-step budget at 50,001 observed steps (p50 24,250.342 µs, p95 39,136.822 µs, p99/max 41,004.194 µs). The resume API returns control to its caller but does not schedule an event-loop turn.

The line-position microbenchmark observed 4,042 work units for a plain snapshot that builds its line index cooperatively (p50 799.041 µs, p95 1,895.789 µs, p99/max 2,104.997 µs) and 2,036 with a document-owned indexed lookup (p50 791.583 µs, p95 1,451.956 µs, p99/max 1,563.416 µs) on 2,006-unit input. These are same-host exploratory measurements, not an editor responsiveness claim. The retained full measurements are in `.artifacts/patterns/T096-nfa-benchmark.json`.

## Failure cases and recovery

The regular NFA test verifies deterministic budget exhaustion at the configured limit, cancellation between resumable slices, oversized repeat compilation returning `program-limit-exceeded`, and output-limit failure returning a source span. The existing zero-width regression verifies bounded advancement and capture behavior. The nonregular fallback benchmark verifies explicit step-budget failure rather than a successful no-match result.

The compiler enforces bounded inputs: pattern source is limited to 65,536 UTF-16 units, capture groups to Vim's nine, nesting to 128, expanded repeat counts to 4,096, and NFA programs to 100,000 instructions. Exceeding a resource cap is a typed error with the source range; these caps were not benchmarked for compile-time latency.

## Limitations and next action

T096 evidence covers its assigned core regular evaluator slice only. Broader VP rows remain partial until their owners pass acceptance:

- VP-01, VP-02, VP-03 regular grouping/alternation, VP-04, VP-05 default regular classes, VP-06 regular newline atoms/classes, VP-07 capture behavior, VP-09 regular spans/anchors/zero-width behavior, and VP-15 regular NFA budgets have T096 fixture evidence. This does not claim those entire VP rows are closed.
- VP-02 command last-pattern state, VP-06 command range/undo behavior, VP-09 command advancement, VP-12 and VP-14 remain T027 integration work.
- VP-03 branch intersection and optional atom sequences, VP-07 backreferences, VP-08 assertions/atomic patterns, and VP-11 engine/combining/code-point behavior belong to T097. Current unsupported forms are typed and source-spanned; they are not treated as a permanent parity boundary.
- VP-05 option-dependent and Unicode class behavior, VP-09 coordinate boundaries, VP-10 positional context, and VP-16 cross-coordinate behavior belong to T098.
- VP-13 arbitrary Vimscript replacement remains outside the product boundary described in the architecture specification.

For newline-inclusive classes, direct `matchstrpos` spans are compared across the flattened snapshot. Neovim buffer `:substitute` treats line-crossing class matches differently from that string-level span oracle, so class cases intentionally do not use `:substitute` output as the evaluator oracle; T027 must verify the command-level behavior. The benchmark also makes no claim about event-loop scheduling, integrated editor latency, or terminal paint.

The ledger remains owned by the parent agent. The recommendation is that T096 may be reviewed for its scoped acceptance while T026 and all downstream VP rows remain open according to their dependency owners.
