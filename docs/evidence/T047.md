## Observable result

`LanguageServerSession` owns one immutable identity consisting of server config, resolved root, workspace ID, environment and workspace folders. `LanguageServerPool` keys sessions by that complete identity, so two roots or workspaces cannot accidentally share a language process. `resolveLanguageRoot` walks absolute file paths from the nearest directory upward, applies root markers in declared order, reports duplicate-marker ambiguity and probe failures, and supports an explicit single-file fallback.

`activate()` starts asynchronously and returns immediately, allowing document admission while spawn and initialize are pending. The lifecycle transitions through starting, initializing, ready, stopping, failed and disabled states. It sends LSP initialize/initialized, retains negotiated capabilities, serves `workspace/configuration`, records dynamic registrations and progress notifications, and reports unknown unregistrations in health. Retry uses the injected `ClockPort`, exponential bounded backoff and a restart-storm limit. A non-retryable executable failure becomes a typed disabled health state.

Open document snapshots and configuration are retained by the session. After a process crash, the replacement server receives exactly one configuration notification followed by one `textDocument/didOpen` for each currently open document. Shutdown is bounded: `LanguageTransport.shutdown()` now limits an unresponsive shutdown request by its shutdown deadline before process cleanup/escalation.

The transport implementation is in `packages/services/language/transport.ts`; `index.ts` is a public barrel so lifecycle can depend on transport without a same-owner import cycle.

## Performance and visual evidence

No visual or keystroke budget is attached to T047. The no-blocking acceptance is exercised by checking the session remains in `starting` immediately after `activate()` while `openDocument()` has already synchronously admitted the snapshot. Retry delay is injected through a deterministic fake clock; no wall-clock backoff is used in the lifecycle owner.

## Failure cases and recovery

- `LSP-T047-ROOT-AMBIGUOUS-01`: duplicate configured marker names return `ambiguous-marker` rather than selecting a root by incidental iteration.
- `LSP-T047-RESTART-STORM-01`: retryable spawn failures stop at the configured retry limit and leave `failed` health with a bounded retry count.
- `LSP-T047-UNAVAILABLE-01`: a non-retryable `ENOENT` process failure leaves `disabled` health with an actionable executable-unavailable reason; explicit `restart()` can clear that state.
- `LSP-T047-UNREGISTER-UNKNOWN-01`: an unknown dynamic capability unregistration is diagnosed and does not corrupt the registered capability set.
- `LSP-T047-REPLAY-01`: after an injected process crash, the new process receives configuration once and the open document once, in deterministic order. Session disposal wakes pending lifecycle waits and transport shutdown escalates within its bounded deadline.
- `LSP-T047-PROBE-FAIL-01`: a marker probe failure is returned as a typed root-resolution failure with the candidate path and platform failure.

## Limitations and next action

This ticket intentionally does not implement versioned `didChange` synchronization, UTF-8/16/32 position conversion, diagnostics, completion, navigation, workspace edits or real-server capability qualification; those are downstream tickets T048 and later. Root marker probing remains an injected platform callback until a filesystem service supplies the production adapter. The current next ready list is available with `python3 tools/plan.py next`.
