## Observable result

The core document, selection-set, parser, command-registry, layout and hit-map contracts have deterministic focused suites. T015 adds a negative import-graph sentinel for a UI-to-document import, compile-time sentinels that reject document mutation through `WorkbenchReadPort` and reject a raw number where a branded UTF-16 offset is required, 1,000 create/subscribe/dispose lifecycle cycles, and an exploratory benchmark for representative operations across the same core owners.

Invalid document batches remain atomic under the T011 generated and boundary cases. Singleton selection sets pass through the selection and parser fixtures; command dispatch and frame-versioned hit maps pass their own focused contracts. This qualifies the core APIs and ownership boundaries. It does not claim that a Vim motion has been executed through a production editor UI: the multi-command engine, minimal terminal editing preview and application shell remain downstream tickets.

The 10,000-member selection-map p95 of about 335 ms is a scale risk worth carrying into T089/T062. It measures only the map operation on a 50,000-unit document; it does not include full command preparation, a 1 MiB workload, cancellation responsiveness or rendered output, so it does not pass or fail the full 10,000-member interaction budget. Existing T009 and T014 evidence reports cover storage and pure viewport projection separately. No production UI exists to inspect visually; integrated typing/output, renderer, startup and terminal performance remain unmeasured.

## Failure cases and recovery

- T011 invalid, stale, overlapping and ambiguous transaction batches leave text/history unchanged; generated anchor maps agree with the reference.
- T012 corrupt or incompatible persisted history is rejected without altering text, version, revision or history.
- T013 malformed continuations, Escape/focus cancellation and mode mismatch remain covered by deterministic parser cases and oracle fixtures.
- T075 wrong-version, invalid-coordinate and duplicate selection inputs are rejected or canonicalized according to the selection contract.
- T085 stale frame/version hits and invalid/oversized targets are rejected before publication; the collision regression verifies distinct fold geometry and identity.
- The UI package currently receives a read-only workbench contract. The graph sentinel rejects a direct UI-to-document import; the type sentinel rejects mutation through the read port. There is not yet a production editor widget in which to test a hidden duplicate text store.
- Initial benchmark-harness runs exposed setup mistakes (reusing an outdated document version, an unwrapped undo-group ID, and an Insert caret for a Normal parser state). The fixture setup was corrected; the final benchmark above exited successfully. No product implementation was affected.

## Limitations and next action

G1 core-contract qualification is complete, and T015 does not claim that the product is launchable. The aggregate `test:unit` suite still needs real fixture wiring. The production UI/mutable-text-copy case, Vim command execution through a real terminal editor path, integrated render/output budgets, and the large selection workload remain for their owning downstream tickets. `T033` must pass before `T034` builds the first light workbench shell; final release claims remain gated by G6.
