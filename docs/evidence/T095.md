## Observable result

`ViewSelectionPersistence` stores schema-versioned member coordinates, primary identity and per-view scroll state separately from document text. `WorkbenchSession` captures every live split view, validates content identity and open-view identity before rebuilding selections, installs all valid view states through the owning atomic coordinator and restores scroll without a document commit. A failed disk or closed-view restore leaves the current selection state and document text intact.

## Performance and visual evidence

Selection persistence is off the ordinary keystroke path and bounded by live views and selection members. It does not copy document text or emit document changes during selection-only recovery. Full retention and large-scale selection qualification remains under T089/T110.

## Failure cases and recovery

Unknown schema, invalid coordinates, changed content and closed targets fail before state installation. Restoration clamps only to the current document’s validated UTF-16 length and rebuilds semantic endpoints against the immutable snapshot. Failed recovery does not erase text or replace the current selection state.

## Limitations and next action

The persisted selection API is explicit and production-owned; automatic workspace policy for when a host saves/loads selection snapshots remains part of later session/release composition. No performance qualification is claimed here.
