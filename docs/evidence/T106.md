## Observable result

`tools/perf.py resolve` now resolves an immutable run ID, unique full source-manifest SHA-256, or unique full recorded Git revision. Missing, stale, ambiguous and self baselines cannot compare. Revision indexes are derived, additive SQLite tables; imports remain atomic and immutable.

The adapter catalog now declares 53 deterministic workload variants across
PF01–PF12 and expands the 55 budget adapters into 1,016 unique
workload/metric/statistic cells. Every cell records its generator selector,
correctness assertion, cold/warm state set, producer boundary, metric source and
sample policy. Observation rows carry the variant ID, and the ledger retains
legacy rows under an ineligible marker instead of counting them toward current
coverage. Declared cells are still distinct from runnable, observed and
qualified cells.

`tools/perf.py status` now reports declared, runnable, observed and
reference-classified counts separately. The current catalog reports 1,016
declared cells, 0 runnable producers, 0 observations and 0
reference-classified cells. Reference-classified rows still do not release
qualify the matrix without complete coverage and host/protocol gates.

`compare BASELINE CANDIDATE [BUDGET-ID ...]` rechecks retained artifact hashes, manifest identities, exact corpus/environment/protocol compatibility and raw metric coverage. It recomputes imported statistics from finite samples, matches units/parameters, checks both runs' minimum sample counts and rejects summary-only evidence. Selected numeric comparisons use actual baseline distributions. Candidate absolute failures or a significant >10% p95 regression fail even inside the other absolute targets. A CI crossing the threshold is unproven. The independent-trial bootstrap uses 2,000 resamples, seed 41027; session-correlated typing and derived comparison metrics require further adapters.

Every comparison explicitly reports `release: unproven`. Source-manifest hashes bind supplied manifests; they do not authenticate production measurement or a dedicated host. Full production provenance, host certification and coverage remain unfinished. See [artifact format and command documentation](../../bench/performance/README.md).

`tools/verify-suite.ts` now rejects missing/repeated option values, missing explicit fixture files, empty required roots, invalid manifests and unregistered benchmark selectors. `bench/manifest.json` lists actual executable benchmarks so diagnostic helpers requiring arguments are not accidentally run by aggregate discovery. The unit suite now runs five previously omitted standalone document scripts (`verify`, T010, T011, T012, T101), and the Python performance regression suites. Every required document script is checked for existence before any fixture executes.

Reference classification now has an explicit provenance guard: a ledger run must
carry a dedicated host ID, qualification method and SHA-256 qualification evidence
identity, and comparison revalidates that the raw artifact carries the same host
metadata. Missing, shared-host or mismatched metadata is rejected. This is a
schema/integrity guard; the current shared VM remains diagnostic and no host has
been qualified by this worktree.

The pinned-runtime sampler is now shared by diagnostic probes in
`bench/performance/runtime-accounting.ts`. It records CPU and wall timing,
signed process/JSC retention deltas, current and peak native commit, process
RSS, and caller-supplied worker attribution. JSC `extraMemorySize` remains a
separate inclusive field; wrapper and total-allocation counters explicitly
remain unsupported on Bun 1.3.13. `tests/performance/t106-runtime-accounting.test.ts`
checks these distinctions and the negative-delta path.

The aggregate `--baseline` option now resolves real raw baseline evidence and explicitly fails on the remaining missing invocation-bound candidate producer. It no longer logs an arbitrary label and reports success. Connecting all production producers remains T106/T115 work, not a suppressed gate.
