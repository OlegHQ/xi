## Observable result

`VimRegisterBank` is an immutable register owner. It supports unnamed, named and uppercase append registers, the numbered delete ring, small-delete `-`, black-hole `_`, register `0` yank behavior, and blockwise values carrying their display width. Explicit named yanks leave register `0` unchanged, matching Vim; explicit named deletes do not rotate the numbered ring. Every failed or black-hole operation leaves the prior bank available to the caller.

`prepareVimPut` emits a pure, versioned-document edit plan for characterwise, linewise and blockwise `p`, `P`, `gp` and `gP`. It reports inserted and cursor ranges, handles final-line linewise separators, emits one edit per block row, supports optional visual replacement (including rectangular block metadata), and never mutates the source register. Clipboard import/export uses the existing typed `ClipboardPort`; a denied read or write is returned as a platform failure and cannot destroy internal yanks.

## Performance and visual evidence

Visual evidence is not applicable to the pure register/put planner. No latency target is claimed; plans are bounded by register line count and document snapshot line reads. Clipboard calls are asynchronous through the platform port and do not block or mutate document state.

## Failure cases and recovery

Uppercase append preserves the lower-case destination's prior value and type. Explicit named delete and small-delete avoid unintended numbered-ring rotation. Black-hole writes return the unchanged bank. Invalid register values, invalid block widths and invalid contexts fail before producing edits. Final-line linewise puts create the required separator. Clipboard denial returns a typed platform failure while the prior internal bank generation and values remain unchanged. Visual plans replace only their supplied range and retain the original source register.

## Limitations and next action

This ticket covers the immutable register owner and pure put preparation. Command-level parser/dispatcher routing, multi-selection broadcast policy and full editor transaction publication remain follow-up integration work; no unsupported clipboard failure is converted into a successful put.
