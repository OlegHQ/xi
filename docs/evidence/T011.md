## Observable result

`TextFileDocument` is the public mutable text owner. A validated factory creates it around private rope storage; the package barrel no longer exports `RopeDocument` or its raw mutators. Runtime backing state uses ECMAScript private fields, persistent rope chunks and nodes are frozen, and immutable snapshots expose no mutable text root or line-ending sequence. This prevents callers from changing text without a corresponding transaction or EOL update.

`commit()` validates document identity, expected version, origin, undo group, UTF-16 boundaries, LF-normalized well-formed replacement text and edit conflicts before applying anything. It canonicalizes edits once into document order, reuses that order for the change map, reverse EOL transformation, rope application and immutable event. Coincident insertions are rejected; zero-width insertions directly touching a nonempty edit are rejected as ambiguous; adjacent nonempty edits remain valid. Invalid or no-op batches leave text, version, revision identity, dirty state and event stream unchanged.

`DocumentChangeMap.mapSortedAnchors()` maps sorted UTF-16 endpoints in one sweep over canonical edit spans. Left/right behavior is defined at insertion points and replacement/deletion boundaries. A successful batch advances `DocumentVersion` and emits one frozen event shared by all subscribers. Reentrant commits are rejected during publication. Listener exceptions are captured in a bounded drain queue so one observer cannot interrupt later deliveries or make an already-applied commit appear rejected. Save completion marks the captured revision identity, so finishing an older save leaves newer text dirty.

## Performance and visual evidence

The sorted anchor mapper uses O(S+E) work for S supplied sorted endpoints and E canonical edit spans. Batch preparation sorts once and reuses the canonical list. The repository assigns the 1/10/100/1,000/10,000-selection scale suite to later selection integration; this ticket does not claim end-to-end multi-selection performance or UI rendering. No visual evidence applies because T011 does not render UI.

## Failure cases and recovery

`T011-INVALID-BATCH-01` covers stale `expectedVersion`, overlapping ranges, same-position inserts and ambiguous insert/replacement boundaries. `T011-ANCHOR-AFFINITY-01` covers anchors inside a deletion, at replacement boundaries and at an adjacent-edit seam; invalid UTF-16 surrogate splits and unsorted endpoints fail explicitly. `T011-GENERATED-OVERLAP-01` confirms invalid batches in either proposal order preserve text, current/saved revision, dirty state and the change stream. `T011-LISTENER-DELIVERY-01` confirms a throwing listener is reported and later subscribers still receive the commit.

## Limitations and next action

The actual undo tree, branching/undo restoration and cross-view selection restoration remain owned by T012; this ticket establishes revision identities and undo-group metadata but does not claim those features. At this layer, rejected proposals cannot create a revision transition or change event. No T011 acceptance item remains unmet.
