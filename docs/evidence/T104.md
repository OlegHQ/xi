## Observable result

`packages/vim/operators/advanced.ts` prepares versioned, atomic plans for external filters (`!`), provider-owned folds (`zf`, `zF`, `zD`, `zE`) and numeric `<C-A>`/`<C-X>` changes. Filter providers receive argv tuples and byte output limits; no shell or process call occurs in the Vim owner. Fold providers return validated line changes without mutating document text. Numeric edits parse `nrformats` (`bin`, `hex`, `octal`, `alpha`, `unsigned`), preserve prefixes/width and return UTF-16 document edits. All plans retain register/history effects, source versions and cancellation/stale guards.

## Performance and visual evidence

No separate latency or rendered-visual budget applies to this pure planner. Filter output has a bounded byte budget and provider work is cancellable; process execution remains a typed platform integration responsibility.

## Failure cases and recovery

Missing filter/fold providers, nonzero provider exit, thrown provider errors, cancellation, invalid argv/options, malformed UTF-16 output, output floods and invalid fold regions return typed failures before publication. Numeric number absence, invalid `nrformats`, stale versions, invalid cursors and overflow preserve the source snapshot and produce no partial edit.

## Limitations and next action

Filter process execution, fold storage/rendering and transaction publication remain downstream service/workbench responsibilities. The provider boundary intentionally does not guess output when a service is absent. T105 owns the aggregate structural/operator qualification that follows this ticket.
