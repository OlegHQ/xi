## Observable result

The spike compared persistent augmented piece descriptors with bounded chunked-rope leaves under the same seeded treap and aggregate logic. Both candidates passed 250 random reference edits, line lookup, stable snapshots, undo, sorted/reversed batch application, cancellation and surrogate-boundary checks. Batch edits use one base version, are applied from high to low offsets and publish one root/version only after preparation succeeds. The anchor mapper advances sorted anchor/edit sequences in one sweep and sorts reversed inputs once.

The measured choice is a chunked rope with leaves capped at 1,024 UTF-16 code units. The 100,000 same-middle insert fixture produced identical text and SHA-256 for both candidates. In the latest reproducibility run it left 100,002 piece nodes and 40,212,685 bytes of retained heap for the piece tree, compared with 539 rope chunks and 616,212 bytes for the rope. T009 now owns the selected production implementation and the measured chunk-count/heap/RSS budget. The detailed timing table, complexity, costs and rejection reasons are in the [T004 storage decision](../decisions/T004-storage.md).

## Performance and visual evidence

The memory probes run one fresh Bun child per candidate. A T007 reproducibility run replaced the benchmark's fixed `.artifacts/buffer/T004-results.json`; this report now records the latest run and that raw artifact, while the earlier raw JSON is no longer retained. For the 100,000-insert workload, the piece-tree child retained 40,212,685 heap bytes and 95,412,224 RSS bytes after GC; the rope child retained 616,212 heap bytes and 66,752,512 RSS bytes. The 1,000-root undo workload retained 1,049,576 UTF-16 payload units / 8,830 unique nodes for the piece tree and 1,549,076 units / 13,021 nodes for the rope. Heap deltas were zero for this undo sample, while RSS deltas were 655,360 and 2,490,368 bytes respectively; the report preserves these observed values without using them as a release claim.

The spike has no UI or terminal output boundary, so screenshots, PTY latency and visual review do not apply. Timings are inner data-structure measurements on a virtualized host with no CPU model exposed; outliers remain in the raw result and no result is described as end-to-end editor performance.

## Failure cases and recovery

- `FC-T004-SURROGATE-01`: a split-surrogate edit is rejected before commit; both candidates retain the original text and version.
- `FC-T004-CANCEL-01`: cancellation after 5,000 prepared edits discards the private candidate root; both candidates retain their original text and version.
- `FC-T004-FRAGMENT-01`: repeated insertion at the same middle offset preserves the explicit reference text. Its deterministic piece-node growth and memory use are the reason the piece tree was rejected for production selection.
- During fixture authoring, the first expected fragmentation digest contained a typo. The benchmark rejected it before writing results; the expected string was independently constructed as 4,096 `a` units, 100,000 `x` units and 4,096 `a` units, its hash was recomputed, and the corrected fixture passed both candidates. The corrected expected digest is `39e8e9fdf7d3e87aee21b8a8ab56670f99fe8887bc6c9b9d0118b4a6e9afbb27`.

## Limitations and next action

These are feasibility prototypes, not the production document package. The two candidates share a randomized treap scaffold, so results isolate leaf payload representation and are not a comparison of all possible tree algorithms. Memory deltas are one isolated sample per candidate and depend on Bun/runtime allocator behavior; deterministic node/chunk and UTF-16 payload counts are reported alongside them. T009 implements the selected chunked rope against the resource budget in the decision record. Release-wide performance, 10 MiB/100 MiB files, real terminal throughput, larger undo branching and final host qualification remain unproven.
