## Observable result

The CLI now provides `--help`, `--version`, `--health` and `file[:line]` argument parsing. The source entrypoint and a Bun compiled Linux ARM64 binary both run the help/version probes without a Neovim process. The normal source launch continues to restore its terminal on quit. The packaging audit records the selected OpenTUI native asset and verifies its lockstep version, checksum, optional dependency declaration and third-party notice. A compiled binary was also run from an isolated directory with an empty HOME and PATH through a real PTY.

## Failure cases and recovery

Missing file reads return an explicit CLI error path; OpenTUI startup and renderer errors remain typed and terminal cleanup is owned by the UI adapter. `--health` does not spawn an external editor engine.

## Limitations and next action

The packaged distribution contract is incomplete: only Linux ARM64 has been exercised as an advertised target, no installer is retained, and packaged no-Neovim E19–E25 workflows are not all available. The launcher currently proves basic file-line navigation, motion, insert, direct change, save, undo, native Ex write/quit/dirty refusal, quit and interrupt paths; pointer, split/restore, multi-cursor, contribution and full session/recovery journeys still require production routing. The dependency/native notice and checksum inventory is retained in `docs/installation/`, but grammar assets are explicitly absent. Keep T064 unproven until the complete editor workflows and final distribution matrix are exercised.
