## Observable result

`packages/vim/ex/index.ts` parses one Ex command or a `|` sequence with source-aware metadata. It recognizes reviewed native names and abbreviations, comma/semicolon/`%` ranges, current/last/numbered/relative/search/mark addresses, offsets and escaped delimiters. Global patterns and substitute payloads retain pipes and escaped delimiters as data. Nested global commands fail before preparation.

The planner resolves all addresses against one immutable document snapshot and emits pure UTF-16 `DocumentEdit` plans, register effects and typed host effects. It implements global/vglobal, normal command composition, linewise move/copy/delete/yank, substitute/repeated substitute, and write/edit/quit effects. Ex plans use one deterministic Vim undo-group identifier and are consumable by the document transaction/history owner; no file or process IO occurs in the Vim module. Each plan records document-once execution and explicit primary-range semantics for multi-cursor callers.

## Performance and visual evidence

No separate T028 performance threshold is specified. Address resolution and global matching are bounded by the immutable snapshot and the inherited Vim pattern evaluator budgets. Ex prepares one atomic edit set and never publishes a partial result. This is a pure parser/planner change with no rendering path, so visual evidence is not applicable.

## Failure cases and recovery

Invalid ranges, missing marks, missing search-address matches, malformed delimiters, unknown commands and missing command arguments return source-offset failures before an edit plan exists. A nested global command is rejected before any nested preparation. Unsupported normal keys and expression replacement (`\\=`) return typed failures; the test verifies that the failed expression replacement produces no edits. A destination inside a move/copy source range is rejected. Host commands return inert typed effects and perform no IO. Ex edits committed through the document owner use the same version checks and undo history as normal Vim edits.

## Limitations and next action

Expression replacement and arbitrary Vimscript remain the explicit VP-13 architecture boundary. The Ex module accepts already provided document path/range context; command dispatch, filesystem/process execution, full undo/view publication and the broader normal-key dispatcher remain with their owning workbench/Vim layers. The `:normal` planner intentionally handles the exercised atomic keys (`dd`, `x`, `X`, `D`, `J`, `~`) and returns a typed unsupported result for other bodies instead of silently treating them as no-ops. T028's required parser/planner acceptance is covered; the public barrel now exports the Ex API.
