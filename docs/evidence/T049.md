## Observable result

The language session validates and forwards `textDocument/publishDiagnostics` into
the service-owned `DiagnosticStore`. Published versions are generation-bound;
older notifications, malformed ranges/severities, unknown documents, closed
documents and crashed-server entries cannot replace current results. Diagnostics
retain URI, UTF-16 range, message, severity, source, code, server identity and
document version.

The Problems surface is a read-only OpenTUI consumer with a hard total row bound,
count header and truncation footer. The launcher exposes it through `Space d`,
`Space e` and `Space v p`; Esc closes it and returns input to the editor.

## Performance and visual evidence

The service publishes one immutable snapshot per protocol notification and the
Problems renderer clips to its configured row count; it never renders all 10,000
rows. No numeric editor-latency or reference-host qualification is claimed here;
those obligations remain in T106/T109–T118/T115. The PTY fixture verifies the
production route and cleanup, while visual qualification remains part of the
workbench UX gates.

## Failure cases and recovery

- `T049-STALE-01`: a publish below the marked document generation is rejected.
- `T049-E07`: a publish with an older explicit LSP version is rejected; a current
  empty publish replaces the prior server/URI result set.
- `T049-CLOSE-01`: closing a URI removes diagnostics from every server; session
  shutdown clears the server-owned entries.
- Invalid payloads are rejected at the LSP boundary and recorded as lifecycle
  failures without entering the Problems model.
